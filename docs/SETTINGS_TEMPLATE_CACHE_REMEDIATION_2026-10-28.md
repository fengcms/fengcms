# 站点设置与模板缓存一致性修复

依据[审阅报告](SETTINGS_TEMPLATE_CACHE_REVIEW_2026-10-28.md)处理 TC01–TC05。实施顺序为设置发布与旧表单保护（TC01/TC02）、模板版本与删除重建隔离（TC03）、编译和清缓存共用协议（TC04/TC05）。保留原前台模板语法与路由。

## 修复内容

1. **TC01：设置成对发布。** 设置行与运行目录的 `site.json` 由同一个文件锁串行协调。写入前持久记录旧/新数据库行及配置文件；数据库写入失败时清除记录，文件发布失败时回补数据库。请求中断留下的记录会在下一次加载配置前核对并恢复旧状态。记录与锁位于私有运行目录，配置文件以同目录临时文件原子发布。若状态已被协议外操作修改，停止自动恢复并返回受控错误。
2. **TC02：设置基线。** 编辑页携带服务器生成的 HMAC 版本，覆盖数据库行与配置文件内容。保存时在同一个锁内复查；旧页面返回 409，浏览器显示冲突提示并保留输入。每次成功发布写入随机修订值，避免同秒保存或内容恢复原值时误认旧版本。
3. **TC03：模板基线。** 各模板/CSS/碎片路径使用独立锁与私有修订值。打开编辑页时读取内容及版本，保存时在锁内核对。保存、删除和同名新建都会先推进修订值；旧页面不能覆盖新文件。继续使用临时文件与原子替换，新建仍以硬链接阻止同名覆盖，空文件及原路径校验保持可用。
4. **TC04：编译与执行。** 渲染持有模板缓存共享锁，直至编译文件执行完；清缓存取得排他锁后才能删除。编译写入、权限设置和重命名必须成功，源文件读取失败也会报错。失败请求返回 500，不再使用旧产物或产生 HTTP 200 空白页；错误详情仍记私有日志。
5. **TC05：完整且幂等地清理。** 前台桌面、前台移动端和后台编译目录逐个清理，缺少某个目录不会跳过其他目录。操作结果反映实际清理的目录数量；重复执行返回缓存已空。拒绝跟随符号链接缓存目录。

## 验证

- `./bin/dev check`：PHP 8.4.27，353 个文件，无语法错误；两个后台 JavaScript 文件通过 `node --check`。
- `./bin/dev test`：主 HTTP/数据库回归 **616 项通过**，原有隔离导入、备份一致性与 MyISAM 结构回归通过。新增双管理员同秒设置冲突、五种模板类型的旧编辑页、模板与 CSS 删除重建、12 组前台请求和清缓存交错。
- 新增隔离设置专项：InnoDB 与 MyISAM 分别验证 SQL 故障、真实文件重命名故障、旧基线冲突及中断记录恢复。新建私有隔离库及运行目录已清理。
- 新增隔离缓存专项：暖/冷缓存写入失败、保留旧时间戳后的清理、三类缓存的单独与整体清理、重复清理、符号链接拒绝和共享锁等待。测试仅在 `/tmp` 的随机目录操作。
- 真实浏览器后台 iframe：一次性超级管理员登录，打开基本设置并保存成功，再打开模板编辑页核对表单与源码显示。测试账号已精确删除；未修改现有模板内容。

## 部署边界

运行目录须与应用进程共享且可写；多台应用节点如果共享模板或数据库，也必须共享用于锁和修订记录的运行目录，并确认文件锁在所用文件系统上可靠。绕过 CMS 接口直接修改数据库、模板文件或编译缓存的程序不参加该协议。旧版运行目录备份与网站数据库应成对保留。生产 PHP-FPM、OPcache 配置、网络文件系统及更高负载下的行为仍需按站点环境复测。本轮未进行生产部署或推送。
