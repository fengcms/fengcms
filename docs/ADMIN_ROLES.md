# 后台固定角色与旧站点升级

后台只有两种固定角色：`super_admin`（超级管理员）和 `editor`（编辑）。没有自定义权限配置。权限由服务端按每次请求核验，隐藏菜单只是界面表现。

| 功能 | 超级管理员 | 编辑 |
| --- | --- | --- |
| “内容”：已启用内容模型、频道栏目、回收站 | 可以 | 可以，含正常增删改查、批量、还原和彻底删除 |
| “相关”：已启用基础模型、留言查看与回复 | 可以 | 可以 |
| “系统”“模块”、数据库备份/导入、模板编辑 | 可以 | 不可以 |
| 图片/附件上传和选取、只读选择模板文件名 | 可以 | 可以 |
| 系统账号管理：创建两种账号、重置凭据 | 可以 | 不可以 |
| 停用、启用及删除编辑账号 | 可以 | 不可以 |
| 停用或删除超级管理员账号 | 不可以 | 不可以 |

报名接口目前不在“相关”菜单中，仍仅超级管理员可访问。编辑可以修改自己的用户名和密码；修改后需要重新登录。超级管理员从“系统 → 系统管理 → 系统账号管理”创建两种账号。超级管理员账号始终不能在此页面停用或删除；编辑账号删除后不能再登录。重置另一位超级管理员的凭据时，需要核验操作者自己的登录密码。账号停用、删除或重置凭据会使已有会话失效。

后台认证码是登录凭据，不是额外的多因素认证。安装器创建的第一个超级管理员仍使用私有配置中的 `ADMIN_CODE`；新建账号和重置凭据时生成 4 位字母数字认证码，至少包含一个字母和一个数字，避开易混淆的 `I`、`O`、`0`、`1`。字母输入不区分大小写。认证码仅显示一次，数据库只保存哈希。原先已生成的纯数字或较长认证码仍可继续使用，直到该账号重置凭据。请通过与密码分开的可信渠道交付认证码；遗失后由其他超级管理员重置。登录同时按账号与来源 IP 限速；仍应保护密码并限制后台的网络访问。

## 新安装

新安装的 `manage` 表包含角色、启用状态、会话版本和独立认证码哈希。安装器创建的第一个账号明确为超级管理员；安装器初始密码规则保持原样。登录后台后进入“系统账号管理”，从列表页点击“创建账号”进入独立表单，可选择编辑或超级管理员；用户名为 5–64 位，以英文字母开头，后续可用英文字母、数字、点、横线及下划线。后台创建、重置及个人修改密码时，新密码至少 8 个字符且不超过 72 字节。创建成功页会显示一次认证码。不要通过 Git 或公开文档传递账号凭据。

## 已有站点升级

先备份**数据库、源码、上传文件和私有配置**，在隔离副本验证，再安排停写窗口。数据库迁移先于新代码部署；旧代码会忽略新增列，因此迁移后到部署前不能创建编辑账号。

有 PHP CLI 的环境，在正确的 `DB_*` 配置下运行一次 `php tools/migrate.php`。该脚本可以重复运行；它保留现有管理员的超级管理员权限，新创建账号的默认角色为编辑。它也执行原有的安全表迁移与仅针对未改动旧示例页脚的许可文字迁移。运行前核查重复用户名；有重复时必须先人工处理，唯一索引不会自动合并账号。

只有主机数据库管理面板、没有 PHP CLI 时，可在站点副本中按顺序执行下列 SQL。示例前缀为 `f_`，应整体替换为实际前缀。**先单独运行第一条查询**，确认结果为空后再运行后面的语句；这些 `ALTER TABLE` **只能执行一次**，不能用于已经具备这些列的库：

```sql
SELECT admin, COUNT(*) AS total FROM f_manage
WHERE admin IS NOT NULL GROUP BY admin HAVING total > 1;
ALTER TABLE f_manage ADD role varchar(20) NOT NULL DEFAULT 'super_admin';
ALTER TABLE f_manage ADD enabled tinyint(1) NOT NULL DEFAULT 1;
ALTER TABLE f_manage ADD auth_version int unsigned NOT NULL DEFAULT 1;
ALTER TABLE f_manage ADD login_code_hash varchar(255) DEFAULT NULL;
ALTER TABLE f_manage ALTER COLUMN role SET DEFAULT 'editor';
ALTER TABLE f_manage ADD UNIQUE KEY admin_unique (admin);
```

第一条查询有结果时，先解决重复用户名，再继续执行。手工迁移还须对照 `tools/migrate.php` 完成既有安全表迁移；已有较新版本的站点可能已经具备该部分。数据库 DDL 不能依赖事务回滚。上线后检查原超级管理员登录、编辑账号的内容与相关功能、系统入口的 403 拒绝、停用账号后会话失效。

## 回退

创建编辑账号后，**不能仅回退旧版 PHP 代码**：旧版没有角色校验，编辑账号可能取得完整后台权限。必须先停用所有编辑账号并确认其不能登录，或把代码和数据库一起恢复到升级前快照。数据库备份导入也应使用与当前代码相同结构的备份；旧结构备份先在隔离站点迁移并验证。

本地开发通过 `./bin/dev up` 对带开发标记的数据库执行幂等迁移；`./bin/dev test` 只在这种一次性开发库中运行。不要用开发初始化工具处理正式站点。
