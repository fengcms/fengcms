## FR03：无二级索引自定义模型的候选扫描

`moduleModel::related()` 现在先对内容表按 `id DESC LIMIT 500` 取物理行 ID，再在第二阶段应用 `status=1`、当前文章排除及标签 `LIKE`，ID 窗口和匹配条件均有上界。首阶段只依赖模型必备主键，所以已发布记录稀疏时也不会为凑满 500 条已发布记录而向更早记录持续扫描。

复验时检查了 `tests/frontend-content-read-regression.php` 建立的无二级索引自定义模型表。`EXPLAIN ANALYZE` 返回 `Covering index scan ... using PRIMARY (reverse)`，实际读取 500 行；测试断言通过。随后相关文章结果仍排除当前记录，按 ID 倒序，8 个标签上限、零条限制和数据库字符集匹配断言均通过。

行为边界：窗口现指最新 500 条物理内容行，草稿也占用窗口；若窗口内草稿较多，较旧的已发布匹配项可能不再出现在相关文章中。此取舍已写入修复记录及回归断言说明，若产品要求全历史精确相关搜索，需单独建立可维护的标签索引。

## FR04：导航按父级有界扫描

新安装结构与 `migrate_classify_navigation()` 为栏目表增加 `(classid(16),nav,sort)` 索引。查询使用经类型约束的父 ID 字符串条件和排序，与该索引前缀一致，并以 `LIMIT` 提前停止；模型启用状态改用 `EXISTS` 条件，不通过外连接造成排序放大。迁移函数检查已有索引定义，可重复执行而不重复创建；隔离回归连续调用两次并确认索引列及前缀长度正确。

复验在隔离栏目表加入 5,000 条同一父级导航记录后执行查询。`EXPLAIN ANALYZE` 显示 `classify_nav_parent_sort` 范围扫描，实际读取 10 行满足 limit，且计划中没有 Sort 节点；导航结果数量和迁移幂等断言通过。
