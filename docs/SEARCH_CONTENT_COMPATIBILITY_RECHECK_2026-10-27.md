## 基线与验证方法

本轮核对 `c80f250..ed557e9` 的 5 个提交，包括链接与栏目路由、搜索页数限制、内容模型大小写、缺失栏目处理，以及后续根路径链接修正。`c2398b4` 为修复说明，`ed557e9` 为忽略本地商品搜索测试模板的配置调整。

## SC01 栏目完整路由与链接根路径

[url()](../system/common/function.php#L373)按末尾数字 ID 识别内容地址，保留整个模型名；栏目地址把完整标识传到控制器，不再按固定下标拆下划线。[栏目控制器](../app/controller/classifyController.php#L57)通过末尾 ID 查询记录，再逐字核对 `project + '_' + enname`。这使合法名称中的下划线不会丢失，同时没有放开任意查询参数拼接。

修复提交 `a856478` 进一步把动态内容链接改成从站点根路径开始的 `/?controller=content...`，与栏目动态链接一致，避免在 `/tags/...html` 等页面下按相对目录解析。两种链接模式的现有辅助函数回归均通过；Nginx 与 HEAD Apache 的 HTTP 检查实际访问了生成的动态链接和旧伪静态链接。

独立重放另检查了 `news_2026` 栏目英文名。完整栏目地址优先匹配自身记录，生成的分页链接使用明确的查询参数，旧栏目第 2 页路径也能读取预期切片。完全相同的历史字符串无法同时表示两种不同含义，新链接避开歧义是本次接受的修复契约。

栏目路径注入 `controller`、编码后的搜索路径注入以及查询串覆盖路由的既有回归继续通过。

## SC02 与 SC03 搜索词往返

[search()](../system/common/function.php#L406)对含 `/`、`&`、`=`、`?` 或以 `_数字` 结尾的词生成 RFC 3986 编码的动态地址，普通词继续生成原伪静态地址。

除了执行开发方新增测试，本轮独立探针在 `URL_TYPE=1` 的真实辅助函数调用下，将生成链接分别送到 Nginx 和 HEAD Apache。中文、`C++`、四类保留字符、字面百分号及数字后缀均保持原词值并找到自己的临时记录。这样补足了现有兼容性脚本主要在动态辅助函数模式下执行的覆盖范围。

原来手工输入 `/tags/part_2.html` 仍按旧分页规则理解，不能据此认定新辅助函数修复失败；这次验收的是新生成的关键词链接不再落入该歧义。旧分页含义得到保留。

## SC04 搜索范围与分页输出一致

[搜索服务](../app/model/moduleModel.php#L258)显式向分页器传入最大 100 页，并在超出范围时显示缩小关键词的提示。[通用分页器](../system/core/page.php#L79)将上限作为可选参数，没有全局限制所有列表。

独立重放插入 1001 条匹配独立关键词的文章，使用可独立预测的时间顺序验证第 100 页确实返回排序第 991 至 1000 条，生成的末页链接也读取这组记录。真实命中总数仍为 1001，第 1001 条属于明确提示的浏览范围之外；这是保留资源上限后的预期行为。

补充边界检查覆盖总数 0、1、1000、1001；限定搜索分页器的页数分别为 1、1、100、100，真实总数不变。不传上限的通用分页器对 1001 条、每页 10 条仍计算出 101 页，未误伤其他列表。

## SC05 模型名严格匹配

[内容控制器](../app/controller/contentController.php#L24)对数据库返回的注册模型名作逐字比较，不再仅依赖元数据查询的排序规则；大小写不一致在查询实际内容表前返回 404。真实混合大小写模型没有被统一转成小写。

在表名区分大小写的本地数据库上，独立检查了小写文章模型、真实混合大小写模型、各自的大小写变体、停用模型、不存在模型及 `Single` 变体。有效内容返回 200；拒绝路径返回 404，没有更新文章阅读次数，没有再出现原来的 500。

## SC06 缺失栏目返回空名称

[classname()](../app/model/classifyModel.php#L34)对小于 1 的栏目编号直接返回空字符串；非零编号查不到记录时也返回空名称。没有通过抑制错误来隐藏空结果读取。

本轮对零栏目、确认不存在的非零栏目以及有效栏目分别请求内容页。正文均可读取，阅读次数每次恰好增加 1；有效栏目名称和真实所属栏目上下文仍保留。本轮 FPM 日志诊断为零，原先 `classifyModel.php:36` 的 Warning 未复现。

## CR01 工作区 Apache 搜索转义回归

**优先级：P2。状态：待修复，仅存在于本轮开始前已有的未提交改动。** 位置：[分页搜索规则](../.htaccess#L23)、[普通搜索规则](../.htaccess#L25)。

两条规则从 `[B,L]` 变成 `[L]` 后，匹配到的反向引用没有在进入查询参数前恢复转义。以下用相同请求分别发送至两套 Apache；程序源码、FPM 和数据库相同，只有挂载的 `.htaccess` 版本不同。

| 请求路径 | HEAD 配置 | 当前工作区配置 |
| --- | --- | --- |
| `/tags/C%2B%2B.html` | 200，关键词为 `C++`。 | 200，关键词为 `C` 后接两个空格。 |
| `/tags/literal%252F.html` | 200，关键词为字面值 `literal%2F`。 | 200，关键词变成 `literal/`。 |
| 中文关键词的编码路径 | 200，词值保持一致。 | 200，词值保持一致。 |

工作区版本运行现有兼容性脚本时，在 `safe rewritten keyword still round-trips` 的 `C++` 对照断言处失败；这是测试断言失败，不是网站响应 500。对应脚本在 HEAD 配置下完整通过 73 项。

由于响应仍是 200，单看状态码或只测试中文会漏掉问题。[修复说明](SEARCH_CONTENT_COMPATIBILITY_FIX_2026-10-27.md)也明确依赖 `B` 保护 `+` 等字符，因此不能把工作区变更直接作为同样通过的配置交付。

**修复要求：**恢复这两处反向引用的转义保护，或实现并验证等效的编码处理。保留现有路径捕获限制及查询串防覆盖行为。完成后在 Apache 重新运行兼容性测试，并明确断言 `C++`、字面百分号、带空格关键词的第一页及分页链接保持完整词值。

本轮没有修改这两条规则。复审开始和结束时工作区文件的 Git blob 哈希均为 `9a7d4971418d66a532a54e36bf578f1ea5dda6ba`；HEAD 对应文件为 `610049d584c79689bf6229787c32219977003e8a`。该差异不应混入本轮文档提交。

## 补充渲染上下文验证

修复同时调整了[模板渲染上下文](../system/core/controller.php#L35)和[分页上下文读取](../system/core/page.php#L24)，避免模板临时补齐的空参数进入分页链接。

本轮使用实际 `controller::display()`，仅替换模板文件解析的测试支架，检查四种组合：原先没有或已有 `_CMS_RENDER_QUERY`，以及模板正常结束或抛出异常。四种情况下分页上下文都只包含进入模板前的参数，模板仍能看到兼容默认值，结束后 `$_GET` 和原有上下文均恢复。实际 HTTP 的下一页与末页访问也已通过。
