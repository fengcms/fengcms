# 安全升级记录与上线门槛

日期：2026-10-26。当前完成本地容器环境和第一批修复，不代表完整安全审计或生产兼容认证。本文只记录项目通用维护结论，不包含任何客户站点的身份、路径或盘点结果；未部署生产环境.

## 已实现

- PHP 8.4 兼容：移除魔术引号依赖、preg_replace /e、旧字符串下标和 each 等运行障碍，更新 mysqli 驱动和模板编译。
- 管理员登录参数化查询、失败频率限制、会话轮换、安全 Cookie、CSRF；写操作要求 POST，限制控制器方法和批量方法调用范围。
- 旧三重 MD5 密码成功登录后升级为 password_hash；兼容旧特殊字符编码。修改密码只修改当前账号，不再全表更新；数据库密码字段扩展到 255 字符。
- 上传及文件管理要求管理员认证，上传要求 CSRF，校验扩展名、实际 MIME 和大小，随机命名；Nginx 禁止上传目录脚本执行。
- 下载、模板及备份路径限制；安装入口关闭 HTTP 访问；隐藏内部目录、配置与备份。
- 模型数组查询/插入/更新参数化，搜索参数化，限制未发布内容访问；留言字段白名单。
- 模板变量默认 HTML 转义，富文本显式 raw；错误详情写日志，不向访客泄露 SQL/堆栈。后台移除远程版本脚本和自动安全小部件。

## 存量站点迁移边界

本仓库的修复记录只描述当前代码，不能据此判断任一已部署站点的实际漏洞或兼容状态。各站可能有独立定制、不同运行环境与数据库结构；迁移前应在站点自己的私有工作记录中盘点源码、配置、数据和上传文件，不将客户身份或服务器信息写入本仓库。

## 后续必须完成的审计和迁移

1. 在受支持的新系统/运行时上建立预发布环境，逐一合并站点定制。当前代码使用 PHP 8 语法，不能直接覆盖到旧版 PHP 环境。
2. 对真实数据库和上传文件做受控副本演练：旧版 MySQL/MariaDB 迁移到 MySQL 8.4 的视图 DEFINER、SQL 模式、零日期、字符集、索引、保留字及数据完整性均需验证。没有自动转换 MyISAM/utf8，也没有验证所有定制表。
3. 完成剩余原生 SQL、动态字段/模型 DDL、模块导入及旧后台备份恢复的专项审计；旧后台备份恢复尚不能作为可靠灾备手段。
4. 更新旧 jQuery、KindEditor 等前端依赖；继续审查 URL 和内联 JavaScript 上下文，HTML 转义不能替代 JavaScript/URL 上下文编码。富文本仅允许可信管理员编辑，尚未引入 HTML 清洗器。
5. 清理被暂时抑制的 PHP warning/deprecation，补齐全业务浏览器验收；检查长于 bcrypt 72 字节边界的旧密码处理及其他会话在改密后的失效策略。
6. 生产 HTTPS、Secure Cookie、最小权限数据库账号、日志轮换、监控、备份保留策略和镜像摘要固定，需要部署阶段配置。

## 发布与回退顺序

- 保存各站完整源码、上传、运行配置和私密配置；用全表锁获取 MyISAM 一致性数据库备份，先实测恢复。仅使用 --single-transaction 不能保证 MyISAM 一致性。
- 在预发布导入现有数据库副本后运行 `php tools/migrate.php`（使用正确 DB_* 环境变量），它仅扩展管理员密码列并创建登录限流表；不要运行开发 bootstrap。
- 逐项验收登录、栏目、内容、搜索、留言、报名、附件、模板和备份；保留原 URL 模式与路由。自定义模板需适配默认转义和显式 raw。
- 通过验收后安排短暂停写、最终同步数据、切换入口并监控；不要直接升级共享 Apache 影响所有站点。
- 旧程序不能识别新密码哈希，回退必须考虑代码与数据库的一致快照以及切换后的新增数据，不能仅回滚 PHP 文件。

参考：[PHP 支持周期](https://www.php.net/supported-versions.php)、[Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)。本机 Docker daemon 为 27.4，Docker 官方对 28 之前版本有 localhost 发布的同网段可达性提示；本环境在 Colima VM 中且已核验 127.0.0.1 绑定，仍不应将其作为公网生产部署配置。

## 后台兼容性修复（2026-10-26）

添加/编辑文章时，旧 CSRF 注入正则在模板编译后匹配 form 标签，将 action 属性中生成的 PHP 结束符误认为 HTML 标签结束，造成表单截断并显示 `&operate=save` 等片段。现改为在编译前按带引号的 HTML 属性匹配表单，插入隐藏字段；已有编译缓存会随编译器修改自动刷新。

上传二进制文件时扫描 PHP/ASP 字符串会误伤正常图片，已移除此字节子串扫描，保留身份认证、CSRF、大小、扩展名、实际 MIME、图片尺寸校验及随机文件名。BMP MIME 别名按同一允许列表匹配。上传安全依赖 Web 服务器禁止上传目录执行脚本；迁移到其他 Web 服务器时必须保留等效限制。

新增文章添加/编辑表单完整性和 CSRF 位置检查，以及含代码样字节的有效 GIF 上传与静态读取检查；目前 75 项回归检查、90 个 PHP 文件语法检查全部通过。未获取用户实际上传失败的原图，使用可稳定复现相同误判机制的 GIF 测试。

Git 忽略私密 .env、上传、缓存、数据库备份、运行时数据、验证截图、编辑器本地配置和临时文件；保留 .env.example。每个关键节点单独提交，修复提交与上一阶段基线分开。
