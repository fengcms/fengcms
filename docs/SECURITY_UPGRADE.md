## 模板排序与在线保存修复（2026-10-26）

模板管理原来直接使用 `readdir` 的文件系统顺序，且旧文件列表函数最多返回约 101 项。现在由模型收集各分类对应的普通文件、过滤目录/隐藏临时文件/符号链接，并按文件名不区分大小写进行 A–Z 自然排序（数字 2 在 10 前），不再沿用该列表上限。模板、CSS、公共片段、自定义碎片和广告列表使用同一规则；列表链接对文件名进行 URL 编码。

本地保存失败的主要原因是源码整体只读挂载。现仅将前台 `template/`、`css/` 绑定为可写，本地文件可直接纳入 Git；PHP 程序和配置仍只读。FPM 的 www-data 用户通过 `.env` 的 LOCAL_UID 与本机仓库属主一致，镜像启动时按需迁移命名卷属主，不扩大源码目录权限。已验证工作进程可写模板和样式、不可写 PHP 程序与配置。该容器变更已在本地重新构建应用，数据库和数据卷保留。

同时修复零字节文件被误判为保存失败、正常模板脚本被旧 WAF 拦截的问题。仅在管理员通过认证、POST 和 CSRF 后，模板源码字段跳过旧关键词过滤；它是可信管理员维护的可执行模板源码，不使用文章富文本清洗规则。其余请求参数的检查保留。保存时校验分类、文件名、模式、内容类型和 2MB 上限，拒绝路径越界及符号链接；先写同目录隐藏临时文件，修改通过 rename 替换，新建通过硬链接发布以避免同名覆盖，完成后清理临时文件。文件系统须支持这些常规操作；当前本地 macOS/Colima 已实测。目录不可写等操作失败会显示具体提示并保留输入。

## 首页“全部”搜索参数修复（2026-10-26）

搜索表单的“全部”选项提交空 `project`，搜索控制器与查询模型均把空值作为全站搜索，但公共 GET 路由校验原先要求所有 `project` 都是非空模型名，因此请求在进入搜索控制器前返回“模型名称不正确”。现仅允许**前台搜索路由**使用空 `project`；其他路由仍拒绝空值及非法模型名。搜索表单的 POST 跳转会省略空参数，已有的 `?controller=search&project=&tags=...` 链接仍可访问。

验证：274 项业务回归、9 项驱动回归和 333 个 PHP 文件语法检查通过；覆盖原报错地址、缺省模型、表单跳转、指定模型、非法模型和其他路由校验。真实浏览器从首页选择“全部”搜索，页面正常显示；搜索已有文章标题 `xxxx` 返回 1 条记录。原报错地址截图保存在忽略目录 `var/verification/search-all-fixed.jpg`。三个商品测试模板仅加入本地 `.git/info/exclude`，不会混入本次提交；未来正式采用这些模板时可自行取消本地排除并单独提交。

## 后台数据库备份重做（2026-10-26）

后台保留数据库备份管理，并新增仅管理员可用的备份下载。旧版 `dbbackup()` 会漏掉空表、改写文本内容，旧版 `dbregain()` 直接执行未可靠解析的 SQL；这两段旧实现和网页恢复入口已移除，历史备份目录保留且明确标为未经验证。新备份由 PHP/MySQLi 在同一连接持有读锁期间流式生成，写入私有目录，附 SHA-256 清单；下载要求管理员会话及 POST/CSRF，校验文件后分块输出。后台不会执行恢复；SQL 应先导入独立空库演练，上传、源码与私有配置另行备份。

缺少 `LOCK TABLES` 权限、数据库含尚未支持的触发器/例程/事件、多个视图、写入失败或超出后台容量/时间限制时明确失败，不发布残缺文件。多个视图可能存在依赖，表名顺序不能保证恢复顺序；目前须改用主机备份工具。PHP 共享主机无需安装命令行数据库客户端，但大库或受限账号仍应使用主机提供的备份能力。开发环境 328 个 PHP 文件语法检查、9 项驱动与 291 项业务回归通过；另将生成的 SQL 导入独立空库并查询表与视图，随后删除测试库和测试备份。此验证不等于所有定制站点或其他虚拟主机的恢复认证。

## 模型导入执行边界重做（2026-10-26）

模型导出改为版本化 `.fengmodel.json`，仅含模块属性、物理列及后台字段/字段类型描述，不包含 SQL 或文章数据。后台导入先校验文件大小、格式、字段名、数据类型及目标站字段类型，再显示预览并以单次确认创建新表；只允许新模型，不覆盖现有表。建表 SQL 完全由程序根据已验证描述生成，其他值使用参数化查询。旧加密 SQL 码不能进入后台执行路径。模型创建时名称不再拼入 DDL，编辑模型仍允许原表名输入框不提交，且禁止更改已存在模型的表名。

开发环境 329 个 PHP 文件语法检查、9 项驱动与 300 项业务回归通过，覆盖模型导出、预览、导入、恶意字段、旧 SQL 拒绝、重复确认和字段配置还原。旧导入码现可用[离线转换工具](LEGACY_MODEL_CONVERSION.md)转换：只解析旧导出器的固定语法并拒绝额外 SQL、未知字段类型和自定义索引；不会连接数据库执行旧 SQL。旧格式把空字符串转成 `NULL`，转换后应检查预览与默认值。新格式无法表达的自定义物理字段或索引仍明确拒绝，不生成可能丢字段的文件。

## 配置、后台会话与 Web 入口加固（2026-10-26）

启动时要求数据库连接、后台认证码和应用密钥来自私有配置或环境变量，并拒绝已知示例密码、认证码与密钥。新增只读 `php tools/config-preflight.php`，核查必填项、已知示例值、密钥长度、数据库连通性及全局高权限，错误输出不包含凭证。旧站点迁移步骤见[安装文档](INSTALLATION.md)；没有自动改密码、更新线上配置或部署。

后台登录新增 60 分钟闲置和 12 小时绝对时限，账号改密码会使其他会话失效；后台主框架在预计过期前五分钟提醒先保存。Apache/LiteSpeed 的 `.htaccess` 现在只放行已知 PHP 入口，并和 Nginx 一样阻断私有目录、安装 SQL、任意 PHP 及旧 Flash 上传目录。两套未使用的 SWFUpload 文件已从发布源码移除。

验证：303 项 HTTP/数据库回归、326 个 PHP 文件语法检查、JavaScript 语法检查及 Docker 中 Apache 配置检查通过。Apache 和 Nginx 实测 `/config.php`、`/install/install.sql`、`/admin/version.php`、上传 PHP 被阻断，公开 CSS 仍可读取。Apache 规则测试容器只用于静态访问检查，不在其中执行 PHP；生产虚拟主机的 PHP 处理器与 LiteSpeed 尚需在站点副本验收。

## 搜索和逐项查询优化（2026-10-26）

搜索保留原有模板调用及 URL，先执行总数查询，再由数据库用 `LIMIT` 返回当前页；排序在时间相同的记录上增加 ID 与地址作为稳定次序。原实现把所有匹配行取回 PHP 后才切片，峰值内存随结果总数增长；现在 PHP 只接收一页，数据库仍需处理前置 `%` 模糊匹配。关键词最长 80 个字符、页码最多 100，每个会话每分钟最多 60 次搜索。会话频率限制无法单独抵御反复更换会话的流量，公开站点仍应在 Web/代理层设置整体请求限速。

栏目树和站点地图原来每个子节点分别读数据库并做存在性查询；现在单次读取栏目表并在内存中构建树。文章标签原来每个标签执行计数与记录查询；现在一条 `IN` 查询完成。页面保留已有链接、总数和分页语法。回归增加了 12 篇临时文章的双页结果与总数、页码及关键词边界，以及嵌套站点地图；306 项业务回归通过。小型开发库不能代表大型客户库的耗时，发布前仍应在其数据副本上执行 `EXPLAIN` 并比较搜索响应时间。

## 新安装数据库默认值与副本迁移工具（2026-10-27）

安装 SQL 的 16 张系统表现均使用 InnoDB/`utf8mb4_unicode_ci`，与新建模型的默认值一致。MySQL 8.4.11 空库通过共用安装函数导入，MariaDB 10.11 隔离容器也完成同一 SQL 导入；两边均核对 16 张实体表的引擎与排序规则。现有开发库保留 MyISAM/utf8mb3，不作自动转换。

`php tools/schema-migration.php --plan` 只读盘点当前库，列出引擎、字符集、视图和潜在超长索引；`--apply` 仅允许名称以 `fengcms_migration_` 开头、明确确认的数据库副本，且每次只转换一张表。隔离副本演练了缺少授权标记时拒绝转换，以及 MyISAM/utf8mb3 表转换后中文和行数保留；测试库和权限已清理。步骤、备份要求与回退边界见[数据库迁移说明](SCHEMA_MIGRATION.md)。
