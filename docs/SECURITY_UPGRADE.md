## 模板排序与在线保存修复（2026-10-26）

模板管理原来直接使用 `readdir` 的文件系统顺序，且旧文件列表函数最多返回约 101 项。现在由模型收集各分类对应的普通文件、过滤目录/隐藏临时文件/符号链接，并按文件名不区分大小写进行 A–Z 自然排序（数字 2 在 10 前），不再沿用该列表上限。模板、CSS、公共片段、自定义碎片和广告列表使用同一规则；列表链接对文件名进行 URL 编码。

本地保存失败的主要原因是源码整体只读挂载。现仅将前台 `template/`、`css/` 绑定为可写，本地文件可直接纳入 Git；PHP 程序和配置仍只读。FPM 的 www-data 用户通过 `.env` 的 LOCAL_UID 与本机仓库属主一致，镜像启动时按需迁移命名卷属主，不扩大源码目录权限。已验证工作进程可写模板和样式、不可写 PHP 程序与配置。该容器变更已在本地重新构建应用，数据库和数据卷保留。

同时修复零字节文件被误判为保存失败、正常模板脚本被旧 WAF 拦截的问题。仅在管理员通过认证、POST 和 CSRF 后，模板源码字段跳过旧关键词过滤；它是可信管理员维护的可执行模板源码，不使用文章富文本清洗规则。其余请求参数的检查保留。保存时校验分类、文件名、模式、内容类型和 2MB 上限，拒绝路径越界及符号链接；先写同目录隐藏临时文件，修改通过 rename 替换，新建通过硬链接发布以避免同名覆盖，完成后清理临时文件。文件系统须支持这些常规操作；当前本地 macOS/Colima 已实测。目录不可写等操作失败会显示具体提示并保留输入。

## 首页“全部”搜索参数修复（2026-10-26）

搜索表单的“全部”选项提交空 `project`，搜索控制器与查询模型均把空值作为全站搜索，但公共 GET 路由校验原先要求所有 `project` 都是非空模型名，因此请求在进入搜索控制器前返回“模型名称不正确”。现仅允许**前台搜索路由**使用空 `project`；其他路由仍拒绝空值及非法模型名。搜索表单的 POST 跳转会省略空参数，已有的 `?controller=search&project=&tags=...` 链接仍可访问。

验证：274 项业务回归、9 项驱动回归和 333 个 PHP 文件语法检查通过；覆盖原报错地址、缺省模型、表单跳转、指定模型、非法模型和其他路由校验。真实浏览器从首页选择“全部”搜索，页面正常显示；搜索已有文章标题 `xxxx` 返回 1 条记录。原报错地址截图保存在忽略目录 `var/verification/search-all-fixed.jpg`。三个商品测试模板仅加入本地 `.git/info/exclude`，不会混入本次提交；未来正式采用这些模板时可自行取消本地排除并单独提交。
