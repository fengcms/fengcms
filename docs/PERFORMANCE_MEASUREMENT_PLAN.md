# 性能测量与优化判定

最初的安全整改没有代表性数据副本，因此不能依据小型开发库的耗时改写查询。现已在维护者控制的隔离副本完成首轮测量，方法、结果及限制见[隔离数据副本的性能基线与首轮优化](PERFORMANCE_DATA_BASELINE_2026-10-27.md)。原始结果保存在私有台账，不提交业务数据或可识别站点信息。

## 样本与基线

1. 记录代码提交、PHP/数据库版本、表引擎、索引、文章/栏目/标签数量、数据量级、缓存配置与硬件配额。副本中的账号和敏感内容按站点规则脱敏。
2. 选有代表性的首页、栏目首页与深层栏目、站点地图、标签页、空结果和高命中搜索。记录请求参数类别，不保存用户搜索内容。
3. 每项分别测冷缓存与热缓存；固定并发和重复次数，记录响应时间的中位数与 P95、SQL 查询次数、PHP 峰值内存及错误日志。重复运行以区分偶发抖动。
4. 对最慢 SQL 采集 `EXPLAIN`，核对实际索引、扫描行数和排序方式；必要时再采集数据库慢查询日志。`LIKE '%关键词%'` 的前置通配符可能阻碍普通索引利用，需以执行计划确认。

## 优化门槛

先定位查询次数随栏目层级或文章数量增长的调用链，再设计批量读取、缓存或索引调整。任何查询或索引变更都要对照基线复测并核对页面内容、排序、可见性和权限；数据库结构变更先在副本演练并准备完整回退快照。没有可复现的收益或出现业务差异时，不进入站点升级包。
