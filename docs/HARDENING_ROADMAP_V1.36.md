# v1.36 后续加固实施方案（待确认）

制定日期：2026-10-26。依据 [v1.36 代码审阅报告](CODE_AUDIT_V1.36.md)和维护者的取舍。本文件是实施方案，**尚未修改应用行为或生产环境**。

## 范围与原则

- 实施审阅发现的 A1、A2、A4 至 A11。A3 历史富文本暂不处理；A12 管理员模板权限边界暂缓。继续清洗**新提交**的富文本，不改既有文章或模板语法。
- 保留后台**创建数据库备份、列出备份、下载备份**，以及**导出和导入模型**。运行时须兼容没有 shell、`mysqldump`、Composer 或系统级安装权限的 PHP 虚拟主机。
- 不直接改生产站点；站点定制、数据库和上传文件先在独立副本验证。每个可验收阶段单独使用中文 Conventional Commit 提交，不混入未跟踪的个人模板文件。

## 阶段 1：重做后台数据库备份与下载（A1）

**使用方式。**后台“数据库管理”保留“创建备份、备份列表”，增加“下载、删除”；显示创建时间、大小、库/表数量、校验值和状态。历史旧格式文件保留并明确标为“未经验证”，不自动当作新格式。旧的网页“恢复数据”入口和直接执行备份 SQL 的逻辑停止使用；恢复走独立空库演练及主机数据库工具的人工流程。本阶段不提供一键在线恢复。界面明确提醒：数据库备份不包含上传文件、私有配置和源码。

**实现。**用 PHP/MySQLi 生成逻辑 SQL 转储，不调用宿主机命令。仅导出当前配置的数据库；列举表和视图，先记录对象定义、引擎和列信息，再在同一数据库连接上按 MySQL 的混合存储引擎规则关闭自动提交、申请全部相关表的读锁，逐行流式写入私有临时文件；保留 NULL、空表、换行、Unicode、二进制值及精确转义，不调用 `compress_html()`。表结构与数据、视图定义按可恢复顺序输出。对触发器、例程及无法可靠导出的自定义对象，要么实现并测试，要么在预检阶段明确拒绝，绝不生成“成功”的残缺文件。完成后写入包含 SHA-256、对象清单和行数的清单文件，再原子发布；失败则删除临时文件，并在 `finally` 中结束事务和释放锁。读锁期间写入会等待，因此界面提示在低流量时段执行，并设置时间、空间和并发限制。

**共享主机边界。**MySQL 明确要求 `LOCK TABLES` 与 `SELECT` 权限；MyISAM 不能用单纯的事务快照取得跨表一致性。权限缺失、锁超时或 PHP 请求时限不足时，操作明确失败并给出主机面板/命令行备份指引，不把无锁导出伪装为可靠备份。大库需要站长使用主机提供的备份能力；本功能有明确容量上限，不能为避免超时而在多个 HTTP 请求之间丢失读锁。[MySQL LOCK TABLES 文档](https://dev.mysql.com/doc/refman/8.4/en/lock-tables.html)。

**存储与下载。**优先使用 Web 根目录外的可写目录；共享主机不能这样配置时，使用当前受 Apache/Nginx 阻断的私有备份目录并增加目录级拒绝规则及安装检查。备份用随机内部 ID，清单中的受控文件名映射，禁止用户输入路径。下载通过管理员会话、POST/CSRF 的 PHP 端点分块输出，设置附件响应、`no-store` 和 `nosniff`；下载前核对文件类型、真实路径、大小和 SHA-256，拒绝符号链接。直接访问文件 URL 必须失败。删除也只接受内部 ID 和 POST/CSRF。按 [OWASP 文件存储与下载建议](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)限制权限、容量与访问。

**验收。**在隔离空库完成备份、下载、校验和恢复演练；比较对象、行数与代表性字段值，覆盖空表、视图、NULL、二进制、中文及补充平面字符、长文本、MyISAM/InnoDB 混用。测试匿名访问、CSRF、路径穿越、锁权限不足、磁盘写入失败、并发创建和超时清理。数据库恢复只在测试库执行，绝不对现有开发库或生产库做破坏性回灌。

## 阶段 2：保留模型导入，替换可执行 SQL 格式（A2）

**新格式。**模型导出改为带格式版本号的 `.fengmodel.json`：只记录模块名称、项目代号、字段定义/类型、排序、显示设置及必要的表结构信息；不包含文章数据、SQL 语句或可执行模板。导入允许用户指定新项目代号，先展示“将创建的表与字段”预览，再确认创建。跨站导出与导入仍可用，原有自定义字段类型在新格式内可表示；遇到本系统不支持的自定义 SQL 类型时明确拒绝，不悄悄丢字段。

**信任边界。**服务端限制文件大小、JSON 深度和字段数量，严格校验格式版本、全部键、字段类型、长度、默认值与项目名；表名/列名只允许校验后的标识符，文本值走参数化查询。DDL 只由程序依据已验证的结构生成，导入文件中的字符串永不作为 SQL 执行。仅能创建新模型，禁止覆盖已有表或模块。导入失败只清理本次创建的对象，记录失败位置；不能把 MySQL DDL 误当成可回滚事务。导出与导入继续要求管理员认证，写操作要求 POST/CSRF；导入正文按结构化格式验证，避免旧关键词 WAF 误拦截正常模型描述。

**旧导入码兼容。**旧加密 SQL 文本不再交给线上导入入口执行。提供一次性**离线转换工具**，只识别本项目旧导出器产生的有限语法，先解析为新格式并展示结果，无法无损解析时拒绝并要求从原站重新导出或人工整理。转换工具不得直接连接目标库执行旧 SQL；用旧导出样本测试字段还原。界面和发布说明明确这是导入文件格式变更，模型导入能力保留。

**验收。**在测试库导出文章/自定义模型、换一个项目代号导入并对比字段和后台表单；测试重复名称、非法标识符、伪造字段、过大输入、SQL 片段、并发导入和中途失败，确认现有数据不受影响。

## 阶段 3：配置、会话及 Web 入口（A4、A5、A6）

1. **配置预防。**新增部署预检查，识别缺少私有配置或环境变量、已知默认密码/认证码/密钥和数据库账号权限过大。新安装缺少必要值时拒绝启动；旧站点先给出私有配置迁移步骤，再移除危险默认值，避免无提示地使现有站点停机。数据库密码只能由站长提供；生成的新随机认证码/应用密钥只写入私有配置，绝不进入 Git 或页面响应。
2. **会话时限。**建议后台闲置 60 分钟、登录后绝对 12 小时强制重新认证；服务器端保存并检查时间戳，改密码使该账号其他会话失效，前端在即将超时时提醒保存。覆盖登录、登出、多标签页、过期 CSRF 与编辑长文场景。PHP 官方建议使用时间戳管理会话，而非只依赖垃圾回收。[PHP 会话安全手册](https://www.php.net/manual/en/features.session.security.management.php)。
3. **部署规则。**对照 Nginx 清单收紧 Apache/LiteSpeed 的 PHP 入口，只开放前台、后台登录/路由、编辑资源 API 和新站点安装器；删除发布包里不再使用的 SWFUpload/示例端点。验证私有配置、SQL、备份、上传和目录文件不可直连，不能只依赖扩展名黑名单。对 Nginx 与 Apache 都做 HTTP 实测。

## 阶段 4：搜索与逐项查询（A7、A8）

- 保留当前“全部模型/指定模型、按标题或关键词匹配、现有 URL”语义，先在生成数据和真实数据副本上采集 `EXPLAIN`、SQL 次数、峰值内存与响应时间，再改为数据库层有界分页、单独计数和稳定排序。对匿名搜索词长度、页码及请求频率设上限。普通 B-tree 索引无法直接解决前置 `%` 的模糊查询；是否使用全文/专用索引由中文搜索质量与基准结果决定。
- 栏目树、站点地图和文章标签改为批量读取及内存映射；需要缓存时设明确的失效点。验收同一内容集上的页面 HTML、分页总数、搜索结果和 URL 不退化，并记录改造前后查询次数与响应时间。

## 阶段 5：依赖、旧 WAF 与持续验证（A9、A11）

- 盘点 jQuery、旧插件与实际调用，先用兼容工具定位废弃 API，再按页面迁移到本地托管的现代版本；旧插件无法兼容时替换相应插件，检查 `.html()`/`.append()` 等 DOM 输入点及后台 iframe 页面。jQuery 官方当前列出 4.x 为主线，1.x/2.x 已停止支持；直接替换压缩文件并不足以完成升级。[jQuery 支持政策](https://jquery.com/support/)、[下载与迁移说明](https://jquery.com/download/)。保留第三方许可和版本来源记录。
- 在具备字段级验证、参数绑定、富文本清洗和输出转义的路径上，用针对性检查取代旧正则 WAF；先写正常内容与恶意输入回归，再逐步移除会误判的规则。开发/CI 显示 Warning 与 Deprecated 并逐项清理；生产仍不向访客显示内部错误。
- 建立 GitHub CI：PHP 语法、无数据库单元检查、容器业务回归、前端检查及依赖来源核验。敏感值来自 CI Secrets；不把测试数据库、上传、缓存或备份提交。CI 测试的环境组合与共享主机验收范围分开说明。

## 阶段 6：新安装默认值与存量数据迁移（A10）

- 新站点安装和新建模型优先使用 InnoDB/`utf8mb4`，选 MySQL 8.4 与 MariaDB 10.11 均支持的字符集排序规则；检查索引长度、字段类型、排序和安装器兼容性。MySQL 8.4 将 `utf8` 视为已弃用的 `utf8mb3` 别名。[MySQL 字符集说明](https://dev.mysql.com/doc/refman/8.4/en/charset-unicode-utf8.html)。
- 存量站点**不自动转换**。提供只读盘点与预检脚本、迁移说明和可在副本执行的分表迁移工具；列出可能的索引长度、数据编码、视图、定制表问题。先用阶段 1 的可验证备份和上传/配置快照演练恢复，再安排停写窗口逐表转换、比较数据与业务验收；失败回到完整快照，不只回退 PHP 文件。

## 交付节奏与提交

各阶段以“功能和异常路径测试通过、文档更新、人工核对暂存区”为完成标准，分别提交 `type(scope): 中文描述`；阶段 1 与阶段 2 可以拆成更多独立提交（后端、界面、回归与兼容工具）。每个阶段完成后报告实际测试环境、未覆盖情形和提交哈希。优先顺序为 **1 → 2 → 3 → 4 → 5 → 6**；阶段 6 的存量迁移仅交付工具与演练方案，任何生产执行另行决定。

确认本方案后开始实施；本文件本身不授权生产部署、生产数据库恢复或发布新版本。
