# 前台内容读取审阅修复记录

依据[审阅报告](FRONTEND_CONTENT_READ_REVIEW_2026-10-28.md)处理 FR01–FR04，并依据[复查记录](FRONTEND_CONTENT_READ_RECHECK_REMEDIATION_2026-10-28.md)补齐 FR03、FR04 的执行计划与迁移索引。未修改模板调用写法。

## 修复内容

- **FR01 停用模型可见性：**栏目路由在显示模板前验证对应自定义模型仍为 `type=1 AND status=1`；动态与伪静态路由都返回 404。栏目树、页头导航和站点地图统一隐藏停用模型的栏目；模型重新启用后，模型写入修订号使当前请求内的栏目树快照刷新。
- **FR02 相关文章结果：**相关文章查询从当前请求的 `project/id` 获取当前文章 ID，并排除自身；结果按内容 ID 倒序，保证多次请求顺序稳定。保留现有模板里的 `related(project, tags)` 调用。
- **FR03 相关文章规模上界：**删除对全部已发布行执行多分支前缀通配 `LIKE` 的查询。查询沿每个合法模型必有的主键倒序读取最新的最多 500 个物理行 ID，不再依赖自定义模型可能没有的 `(status,id)` 二级索引；随后把原有标题/关键词子串 `LIKE` 限定在这批 ID 内执行，保留数据库字符集比较规则。每次最多处理 8 个关键词，每个关键词最多 64 字节，输入最多 1024 字节，返回数量限制为 0–100；当前文章在第二阶段排除。候选读取和 LIKE 匹配集合都有固定上界。
- **FR04 页头导航：**识别原有栏目导航 `l()` 查询后，直接以父栏目、导航状态、启用模型状态、排序和请求 limit 执行 SQL；不再先全量读取并在 PHP 构造栏目树。地图、祖先/子栏目等需要完整树的路径仍使用请求级快照。模板和排序字段选择语法保持原样。

## 相关文章匹配边界

FR03 采用有界候选窗口作为兼容模板的低风险处理方式：子串匹配语义保留，但窗口是 ID 最新的 500 条物理内容行，之后再筛选已发布状态。因此草稿也会占用窗口；若关键词只出现在这 500 行之外，或仅匹配被草稿占用窗口挤出的更旧已发布文章，该文章不会出现在相关文章结果中。ID 用作稳定的近期顺序；若后续需要全历史精确相关搜索，应单独设计可维护的标签索引，并纳入所有内容写入、导入和自定义模型生命周期。
