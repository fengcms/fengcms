# 前台内容读取审阅修复记录

依据[审阅报告](FRONTEND_CONTENT_READ_REVIEW_2026-10-28.md)处理 FR01–FR04。未修改模板调用写法，也未增加数据库迁移。

## 修复内容

- **FR01 停用模型可见性：**栏目路由在显示模板前验证对应自定义模型仍为 `type=1 AND status=1`；动态与伪静态路由都返回 404。栏目树、页头导航和站点地图统一隐藏停用模型的栏目；模型重新启用后，模型写入修订号使当前请求内的栏目树快照刷新。
- **FR02 相关文章结果：**相关文章查询从当前请求的 `project/id` 获取当前文章 ID，并排除自身；结果按内容 ID 倒序，保证多次请求顺序稳定。保留现有模板里的 `related(project, tags)` 调用。
- **FR03 相关文章规模上界：**删除对全部已发布行执行多分支前缀通配 `LIKE` 的查询。查询先利用 `(status,id)` 顺序读取最新的最多 500 条已发布候选 ID，再将原有标题/关键词子串 `LIKE` 条件限制在这些 ID 内执行；这样保留数据库原有排序和字符集比较规则，同时将逐行匹配范围限定在最多 500 条；每次最多处理 8 个关键词，每个关键词最多 64 字节，输入最多 1024 字节，返回数量限制为 0–100。当前文章排除条件也应用于候选读取。这样数据库读取行数有固定上界，表增长不会扩大单次关联查询扫描集合。
- **FR04 页头导航：**识别原有栏目导航 `l()` 查询后，直接以父栏目、导航状态、启用模型状态、排序和请求 limit 执行 SQL；不再先全量读取并在 PHP 构造栏目树。地图、祖先/子栏目等需要完整树的路径仍使用请求级快照。模板和排序字段选择语法保持原样。

## 相关文章匹配边界

FR03 采用有界候选窗口作为兼容模板的低风险处理方式：子串匹配语义保留，但只在 ID 最新的 500 条已发布内容内匹配。因此，关键词只出现在窗口之外的旧文章时，不会出现在相关文章结果中。ID 用作稳定的近期顺序；若后续需要全历史精确相关搜索，应单独设计可维护的标签索引，并纳入所有内容写入、导入和自定义模型生命周期。
