# 已有网站升级指南

这份说明适用于已经运行 FengCMS 的网站。**升级不是首次安装**：不要打开安装向导，也不要把新版本文件直接覆盖到正式站点后才检查结果。

## 升级前先确认

- 当前 FengCMS 版本，以及目标版本的[发布说明](releases/)。
- PHP、MySQL/MariaDB 和 Web 服务器版本；站点是否修改过模板、控制器、模型或伪静态规则。
- 当前数据库表前缀、上传目录、私有配置文件的位置和后台账号情况。
- 目标版本要求执行的数据库迁移。迁移命令可能会修改数据库，不能直接对正式库试跑。

如果站点有无法识别的定制代码、数据库表或外部插件，先让维护人员核对差异。不要把真实配置、密码或客户数据发到公开问题区。

## 第一步：做一份完整、可恢复的备份

升级前保留同一时间点的：

1. 网站源码，包括自己修改的模板和 Web 服务器配置。
2. 完整数据库备份。
3. `upload/` 中的图片、附件及其他站点文件。
4. 私有配置文件，例如 `config.php` 或旧站点的 `config.local.php`。
5. 运行配置和部署记录。

将备份恢复到独立测试站点和独立数据库，确认可登录、数据可读、图片可访问。只下载了备份但没有验证恢复，不算完成备份。数据库备份不包含上传文件、源码和私有配置。

## 第二步：在副本中升级

1. 将生产站点复制到隔离副本，使用单独的域名或本机访问方式，确保不会连接正式数据库或覆盖正式上传目录。
2. 在副本应用目标版本的代码；人工比较并迁移自定义模板和配置。不要把旧版 `system/`、`app/` 或后台程序目录整体复制回来。
3. 在副本的 PHP CLI 中运行配置预检 `php tools/config-preflight.php`，修复列出的问题。该检查不应公开输出数据库凭证。
4. 在副本运行数据库迁移 `php tools/migrate.php`，并记录结果。不要把指向副本的迁移命令改为生产数据库直接执行。
5. 若计划额外改变表引擎、字符集或定制表结构，应把它作为单独项目，在数据库副本逐表检查和演练；这不是普通代码升级的必需步骤。
6. 完成下方的业务检查，并保留失败项和修复方法。

如果主机没有 PHP CLI，先询问主机商是否提供终端或代运行命令的方式。若只能使用数据库面板，必须按目标版本提供的迁移步骤在副本执行并逐项核对；没有明确、适用的 SQL 步骤时，不要猜测或直接升级正式站点。

## 第三步：副本验收

- 超级管理员和编辑账号都能登录，编辑无法进入系统管理、数据库、模板及模型配置。
- 栏目、文章、新增与编辑、回收站、搜索、标签、留言回复等本站实际使用的功能正常。
- 图片和附件可上传、选择、显示；自定义模板与前台链接正常。
- 数据库备份可创建和下载；若需要导入，先按[数据库备份与恢复](数据库备份与恢复.md)在副本演练。
- 私有配置、SQL、备份、程序目录和上传目录中的脚本不能从浏览器访问或执行。
- 检查错误日志，不出现无法解释的 PHP 错误或数据库错误。

## 第四步：安排正式切换

副本验证通过后再安排停写窗口，通知编辑暂停后台操作。切换前重新保存一份生产完整备份，并核对文件可读。按已演练的顺序运行迁移、替换代码、恢复定制模板和更新 Web 服务器配置，然后验证前台、后台、上传、留言和备份。

如果切换失败，先保持站点停写，再成套恢复升级前的源码、数据库、上传文件和私有配置。只回滚 PHP 文件可能无法兼容已迁移的数据库或账号数据。

升级问题可参考[常见问题](常见问题.md)和对应[版本发布说明](releases/)。每个站点的环境和定制不同，不能只根据其他站点或开发容器的结果判断可以直接上线。

## 使用增补升级包

部分版本会同时提供完整包和限定起点的增补包，例如 `fengcms-v1.37-to-v1.38.zip` 只适用于正式 v1.37。更早版本、版本来源不明或存在大量核心定制的网站，应使用完整包并按相应发布说明逐项迁移。

先核对 Release 附带的 SHA-256，并完成上文的备份和副本演练。解压增补包后，先阅读根目录中文说明；只将“网站文件”目录里面的内容按相对路径上传到网站根目录，另行比较“服务器配置参考”，按“需要删除的文件清单”处理明确列出的旧文件。不要将整个增补包当作一个网站目录覆盖上去。

“文件校验清单.json”记录基准和目标提交、每个变更文件升级前后的 SHA-256、文件权限及新增/修改/删除类型。本站文件与基准摘要不同，可能是定制或另一构建，需先比较，不应仅凭后台版本号直接覆盖。摘要与目标一致的文件可跳过。

增补包不携带私有配置、上传、缓存和数据库，也不会自动合并定制、执行 SQL、修改服务器配置或删除文件。数据库是否需要迁移，以对应版本说明为准。覆盖完成后清除前后台模板缓存、强制刷新浏览器，再检查后台版本及站点业务。系统仍不提供后台在线更新。
