# 数据库字符集与存储引擎迁移

从本次加固起，**全新安装**的 16 张系统表使用 InnoDB 和 `utf8mb4_unicode_ci`。新建模型与新格式模型导入同样使用 InnoDB/utf8mb4。既有站点不会因代码升级而自动执行 `ALTER TABLE`。

## 先盘点，再制作副本

1. 在停写或低流量窗口取得完整、可校验的数据库备份，并另外保存上传文件、站点源码与私有配置。先把备份恢复到**空库**，核对表/视图、行数、中文、表情符号、二进制值和代表性页面。不能只留 SQL 文件而不演练恢复。
2. 用站点的私有配置或环境变量，在 PHP CLI 运行 `php tools/schema-migration.php --plan`。默认只读，列出当前前缀内各实体表的引擎、排序规则、估计行数、非 utf8mb4 字段、视图和索引风险，并输出逐表 SQL。表名前缀从 `DB_PREFIX` 或私有配置读取。不要把含凭证的环境文件贴到工单。
3. 将待迁移站点恢复到名称以 `fengcms_migration_` 开头的独立数据库副本，例如 `fengcms_migration_copy`。不要把该名称指向正式库。对副本运行同一个盘点命令；修复索引超过 3072 字节、异常编码、定制表及外键依赖后再转换。

## 仅在副本逐表执行

准备好指向副本的 `DB_HOST`、`DB_USER`、`DB_PASS`、`DB_NAME`、`DB_PREFIX` 环境变量或私有配置后，逐张执行：

```sh
FENGCMS_MIGRATION_COPY=1 php tools/schema-migration.php --apply \
  --confirm-db=fengcms_migration_copy --table=f_article
```

工具要求当前数据库名称以 `fengcms_migration_` 开头，`--confirm-db` 与实际连接的库名完全一致，且一次只能指定一张当前前缀内的实体表。它持有数据库命名锁、设置较短的等待锁时限，执行 `ENGINE=InnoDB, CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`，然后比较转换前后行数。存在估计过长索引或关联外键时拒绝执行。**行数一致不代表所有字节和业务语义一致**；逐表比较代表性字段、排序、查询计划和业务页面。转换会重建表并可能长时间占用空间及阻塞写入；MySQL DDL 不能靠事务回滚。

视图不会由工具重建，应在副本中验证视图查询和依赖关系。定制模型、插件表、旧字符编码及长索引需要个别处理。全部验证完成后，再安排生产停写窗口和完整快照；生产执行需另行决定，不能直接把副本迁移命令改成正式库名。失败时恢复**完整的数据库、上传与私有配置快照**，再核对应用版本，不能只回退 PHP 文件。

纯 PHP 虚拟主机没有 CLI 或足够数据库权限时，使用主机面板的备份、恢复与 SQL 管理工具，在独立站点副本按相同顺序演练；无法确认副本、备份或停写条件时保留原表，CMS 代码可继续读取旧表。
