# 性能审阅落实记录

日期：2026-10-27。对应审阅：[性能与代码维护性审阅报告](PERFORMANCE_CODE_REVIEW_2026-10-27.md)。本轮没有修改 `template/` 或 `admin/template/` 中的文件，也没有改变 `{$变量}`、`{loop ...}`、`l(...)` 等模板写法。

## 已完成

| 审阅项 | 处理结果 |
| --- | --- |
| PERF01 | 编译器为每个循环保存一次数据表达式结果；两种循环语法、空结果和嵌套循环均有独立回归。编译缓存沿用现有编译器文件时间戳失效机制。 |
| CODE01 | `getcount()` 使用临时查询选项，统计时排除排序和分页，完成后恢复字段、条件及参数。覆盖连续统计、分页列表和绑定条件。 |
| PERF02 | 普通模型在同一 PHP 请求内复用同配置 MySQL 连接，模型的查询选项、受影响行数和新增 ID 仍各自独立。直接创建的驱动、事务模型、通过模型执行的会话级 SQL、备份和导入使用独立连接。首页基础设置在请求内只读取一次。 |
| PERF03 | 前台栏目数据及父子索引按请求复用；现有导航 `l(...)` 调用通过内部适配读取同一快照。后台建树改为父 ID 索引，并防止循环引用无限递归。模型写入后请求内快照失效。 |
| PERF04 | GET 页面在进入模板渲染前、资源列表和上传在认证及 CSRF 校验后释放 Session 锁；备份创建、下载及导入在完成必要的会话写入后释放。搜索限流状态在释放前写入。登录、验证码及预览等仍按其状态流程持锁。 |
| CODE02 | 渲染期间保留旧模板读取 `$_GET` 默认值的兼容层，渲染结束后恢复原始请求。内容保存控制器显式传递模型名称，旧 PHP 调用保留兼容入口。 |
| CODE03 | 独立的编译器、模型状态、栏目、Session 和 PHP 诊断回归已接入 `./bin/dev test` 或 CI。CI 对新产生的 PHP Warning、Deprecated、Notice 和 Fatal error 失败，并只输出位置和数量。 |

模型字段能力的重复查询也增加了请求内复用；字段元数据被模型写入后会失效。缓存不跨 PHP 请求，因此不需要部署新的缓存服务。

## 本地验证与测量范围

- `./bin/dev check`：333 个 PHP 文件，语法错误为零。
- `./bin/dev test`：473 项 HTTP/数据库回归通过；隔离数据库导入演练通过；新增的独立回归通过。
- 对一次完整回归开始后的 PHP 容器日志执行诊断门槛，新增诊断为零。
- 本地开发库中启用搜索的文章与商品模型分别只有约 10 条和 2 条记录。`EXPLAIN` 对包含关键词的查询显示全表扫描，但扫描规模很小，不能据此判断真实站点的搜索瓶颈。
- 在这套开发库中，首页、一个内容页和标签页各请求观察到新建 1 个数据库连接。全局连接计数可能受同时运行的任务干扰，不能作为生产容量承诺。
- 改动前后曾分别用少量串行 `curl` 请求采样。此前首页、内容页、标签页中位数约为 92、108、39 毫秒；此后约为 19、20、16 毫秒。两组采样的缓存状态和系统负载未严格控制，这些数字仅供本地回归参考，不作为可归因的提速比例。

## 暂缓的查询改写

PERF05 的搜索 `UNION`、`COUNT`、字段选择与索引暂不改动。当前开发库太小；改变去重或排序还可能影响跨模型结果。下一步按[性能测量与优化判定](PERFORMANCE_MEASUREMENT_PLAN.md)，在维护者控制的代表性隔离数据副本中采集高命中与空结果查询的中位数、P95、执行计划、扫描行数和峰值内存。只有验证结果和收益后，再分提交调整 SQL 或索引。

代码风格和静态分析继续按修改模块逐步收敛，不做全仓格式化或全量类型改写。新增或修改代码应保留清晰的参数与返回约定；提交前使用 `./bin/dev check`、适用回归和 `git diff --check`。本记录不代表已对生产站点执行性能测试或部署。
