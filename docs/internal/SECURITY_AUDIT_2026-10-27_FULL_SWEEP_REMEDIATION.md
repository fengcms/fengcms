# 全仓扫描报告复核与修复记录

日期：2026-10-27。依据[原始审阅报告](SECURITY_AUDIT_2026-10-27_FULL_SWEEP.md)逐条复核当前仓库代码。原始报告作为审计输入保留；本文件记录验证结果和代码变更。没有修改生产站点。

| 条目 | 复核结论与处理 |
| --- | --- |
| B1-01 字段编辑批量赋值 | 确认。更新时只接收编辑表单允许的 `aliases`、`defaults`、`must`、`length`、`enable`、`search`、`nullmsg`、`errormsg`。伪造的物理字段名、所属模型、类型、状态及排序值不再写入元数据；回归验证正常别名修改仍成功。 |
| B1-02 旧元数据进入 DDL | 删列原来直接拼接旧库字段名，已在 `dropalter()` 使用统一标识符校验与引用；删表也在执行前再次验证并引用表名。恶意旧字段名被拒绝，未执行 DDL。模型构造器原本已校验表名。 |
| B1-03 不存在的字段模型 | 后台字段管理的列表、系统字段、新建、修改读路由先查模型；不存在时返回 404，不进入模板或后续查询。 |
| B2-01 编辑列出模板 | 报告将“列出模板源码”与实际响应混淆。`files.php?dir=` 仅返回文件名、路径和文件元数据，不返回文件内容；编辑需要这份列表为文章选择模板。Web 服务器禁止直连 `/template/` 源文件，编辑也不能访问 `tplmanage`。保留功能并加入响应边界回归。 |
| B3-01 前台留言 CSRF | 当前代码已经防护：`cms_route_guard()` 对**所有** `$writable` 路由调用 `cms_post_required()`，其中执行 POST 与 CSRF 校验，并不只适用于后台。缺少令牌的前台留言 POST 返回 403；新增回归防止未来误删。无需重复实现。 |
| B4-01 模板编辑执行能力 | 这是超级管理员的既有信任边界，不是编辑角色提权。已在[安全升级记录](SECURITY_UPGRADE.md)说明“编辑模板等同执行代码”，保留角色限制与 `FENGCMS_DISABLE_TEMPLATE_WRITE=1` 关闭开关；不使用函数名黑名单伪装沙箱。 |
| B5-01 遗留弱加密 | 仓库无调用点，已删除旧 `encrypt()` 函数。站点定制代码若调用该函数，升级前须在副本中迁移调用与旧密文。 |
| B5-02 旧三重 MD5 密码 | 已有登录后升级机制，不宜在未确认站点账号状态时批量重置。当前开发库没有旧哈希账号；其他站点需在私有副本盘点，由超级管理员重置长期未登录账号。 |

## 待验证边界

- V-1：只读检查当前开发库，`f_module_field.name`、`f_module.project` 无不合法标识符，栏目无失效父节点；**没有据此推断生产库**。迁移前在各站副本执行同类检查。
- V-2：后台留言回复表单对访客内容及已有回复走模板默认转义，新增带 HTML 探针的回归。
- V-3：仓库的 Docker Nginx 与 Apache `.htaccess` 示例阻断上传脚本执行及模板源码直连。各站实际 Web 服务器、虚拟主机覆盖规则和上传目录配置仍须部署时现场核验。
- V-4：本地伪静态路由有查询参数覆盖回归；各站生产重写配置可能独立定制，仍须在站点副本验证 `url_type=0/1`、栏目、文章、标签、搜索及异常参数。
- V-5：`classifyModel::classify()/classside()` 与 `model::alter()` 当前仓库无调用点。保留它们以降低旧模板或站点扩展的兼容风险，后续有完整调用盘点时再决定清理。

本轮代码修复均在带开发标记的本地数据库上运行语法检查和 HTTP/数据库回归；这些检查不能替代站点副本的业务验收。
