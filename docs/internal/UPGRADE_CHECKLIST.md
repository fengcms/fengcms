# 存量站点升级检查清单

适用于已有站点的逐站升级。代码回归通过不等于某个定制站点可以直接覆盖上线；站点身份、账号、路径、版本盘点和验收记录放在私有台账，不提交到本仓库。

## 1. 建立私有台账

- 记录当前源码版本、PHP 和数据库版本、Web 服务器、表前缀、表引擎和字符集，以及已启用的 PHP 扩展。核对目标环境满足 [安装环境要求](INSTALLATION.md)。
- 对比定制控制器、模型、模板、插件、数据表和 Web 访问规则；记录上传文件量、数据库体积、后台账号与角色。逐项确定新版会覆盖或无法识别的定制代码。
- 运行 `php tools/config-preflight.php`，并用 `php tools/schema-migration.php --plan` 只读盘点表结构。没有 CLI 的虚拟主机用主机面板完成同等检查。不要把私有配置或命令输出中的凭据贴进公开记录。
- 核对站点实际使用的私有配置。新版的 `config.php` 是只返回配置数组的数据文件；安装器生成的旧 `config.local.php` 仍兼容。历史程序型 `config.php` 不作为配置源，旧版 `define('DB_TYPE','mysql')` 等代码不能复制到新配置；新版数据库驱动固定使用 `mysqli`。详见[配置说明](CONFIGURATION.md)。
- 若站点有报名设置表，先单独核对它的实际字段、主键和行数。后台保存设置只允许更新**有主键且恰好一行**的表；不满足时会拒绝写入，需要先在副本制定该站点的迁移办法。

## 2. 备份并证明可恢复

- 在停写或可保证一致性的窗口，保存**源码、数据库、上传文件、私有配置和运行配置**，记录对应版本及校验值。含 MyISAM 的数据库不能只依靠事务快照；备份方式须保证跨表一致。
- 将备份恢复到独立空库和独立站点副本，核对表、视图、行数、中文、二进制字段、附件与代表性页面。演练从备份回到可登录状态；仅生成备份文件不算完成。
- 后台数据库导入只适合同版本、同表结构的小型站点，且只接受本系统受限格式；容量与权限限制见[数据库导入说明](DATABASE_IMPORT.md)。大库或结构不同的站点用主机数据库工具在副本恢复。

## 3. 在副本完成升级

1. 从目标代码建立独立副本，连接副本数据库和上传文件。先完成私有配置预检，再在有 PHP CLI 的副本运行 `php tools/migrate.php`。该命令会修改数据库，不得指向正式站点。
2. 如需把旧表转换为 InnoDB/utf8mb4，严格按[逐表迁移说明](SCHEMA_MIGRATION.md)只在副本执行；视图、定制表及索引单独核对。没有迁移必要时保留原表结构。
3. 验证超级管理员与编辑登录、角色边界、栏目及子栏目、文章增删改查、回收站、全部/指定模型搜索、标签、留言回复及验证码异步校验、图片和附件、前台模板与面包屑、数据库备份下载，以及本站实际使用的定制功能。定制前台脚本若直接调用 `home&operate=vccore`，须随请求提交页面的 CSRF 令牌。
4. 核查 `/install/index.php` 在已安装站点关闭，私有配置、SQL、备份、上传目录中的脚本不能直接访问。检查 Nginx/Apache/LiteSpeed 的实际规则，不能只凭开发容器的结果推断共享主机安全。
5. 记录失败项、修复提交、测试日期和回退步骤。所有验证通过后，才为该站点安排切换。

## 4. 停写切换与回退

- 约定停写窗口，告知编辑暂停操作；再次取得一致的完整快照并确认可读。准备可立即切回的旧入口和完整恢复介质。
- 按副本演练的顺序执行数据库迁移、代码与资源切换，再验证首页、后台登录、文章、搜索、留言、上传和 Web 防护。任何未经副本验证的新差异都应中止切换。
- 出现需要回退的故障时，保持停写，**同时**恢复匹配的源码、数据库、上传文件、私有配置和运行配置，再验证登录与页面。只回滚 PHP 文件可能与新账号角色、密码哈希或表结构不兼容。
- 切换后保留观察期和备份；记录错误日志与代表性请求结果。是否部署、何时部署由站点维护者对该站点单独决定。
