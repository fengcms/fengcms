## 性能候选的测量与取舍

本轮额外使用合成数据做初步测量，不是生产容量或提速承诺。原始脚本和输出保存在已忽略的 `var/verification/review-performance*`、`review-query-performance*`。文件测试使用容器临时目录和空文件，数据库测试使用随机独立表并清理；不包含业务数据。样本均为本地 PHP 8.4 CLI/MySQL，受容器文件系统与同时运行的开发任务影响，未做受控冷缓存、负载或并发基准。

| 候选 | 观察 | 本轮决定 |
| --- | --- | --- |
| 资源目录扫描/排序 | 30 次采样：1,000 项中位数 1.73ms、P95 2.23ms；8,000 项中位数 16.07ms、P95 28.36ms。仅模拟目录元数据和排序，不含 HTTP、图片尺寸读取 | 保留现有扫描上限；不新增可能陈旧的目录索引。需代表性真实目录和上传/外部文件变更失效设计后再决定 |
| 搜索宽字段统计 | 2,000 行，每行正文约 12KB，30 次采样；派生表 COUNT 中位数 0.343ms、直接 COUNT 0.364ms，两者 EXPLAIN TREE 相同 | 此样本没有改写收益，保留现有语义；跨模型 UNION 和大规模命中仍需独立测量 |
| 模板读取及内容摘要 | 64KB 源文件，30 次采样，中位数 0.470ms、P95 0.548ms | 保留内容摘要校验，不退回可能漏检同秒保存的 mtime 判断 |
| 清洗器初始化 | 约 9.7KB HTML，20 次同进程调用；首次约 206ms、后续中位数约 3.09ms，峰值约 8MB | 首次时间混合库加载与初始化，不能据此归因于关闭定义缓存；CLI 与带 OPcache 的 FPM 也不同。暂不增加序列化定义缓存 |
| 点击数写入与备份门锁 | 源码仍明确要求同步计数与恢复屏障；没有取得代表性并发负载或测得锁竞争瓶颈 | 保持准确计数和备份一致性；不采用异步/近似计数，也不取消屏障 |

因此本轮落地的性能优化是可直接证明减少连接/失效/空查询的 R04；其余候选已记录测量或不足之处，没有为了“优化”改变排序、结果数量、缓存一致性或清洗信任边界。
