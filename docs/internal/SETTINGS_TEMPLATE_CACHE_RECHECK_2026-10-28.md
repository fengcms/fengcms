## TC01 设置失败与恢复已闭合

[设置发布](../../system/common/site_settings.php#L142)在同一锁内核对基线，先记录旧/新行及文件，再更新数据库、发布文件；失败调用恢复，未完成记录由[后续请求恢复](../../system/common/site_settings.php#L113)。

两种设置表引擎分别重放：

- **原 SQL 故障：**用隔离表触发器拒绝本轮标记 UPDATE。实际保存返回 500，整行数据库及 `site.json` 字节与保存前完全相等，无待恢复记录；随后前台仍显示旧名称和 URL 模式 0。移除触发器后，原版本表单可成功重试。
- **真实文件发布故障：**以表读锁使 UPDATE 等待，确认真实设置日志已建立后，将本轮运行目录设为不可写，再释放数据库锁。保存返回 500，数据库已回补为精确旧行、旧 JSON 不变；由于目录仍不可写，日志清理未完成。恢复目录权限后，下一次真实前台请求完成日志恢复，返回正常旧设置，记录消失；原表单再次保存成功。

没有通过手工写入一个成功结果代替恢复。目录权限只作用于本轮运行目录，未放宽原站点权限。该验证覆盖两种引擎的原失败路径及可恢复重试，TC01 可以关闭。

## TC02 与 TC03 旧版本保护已闭合

**设置：**两个真实设置页取得相同版本；管理员一保存新名称和 URL 模式，管理员二从旧页面提交原名称及新描述，返回 **409**，已确认的整行和 JSON 字节均保留。随后提交相同值的成功保存，版本仍变化，原基线再提交也为 409。

**模板：**分别在 `tpl`、`css`、`scrap`、`inc`、`show` 中打开两个编辑页。第一次修改成功后，第二个旧版本返回 **409**，文件保留第一人的内容。[文件发布](../../admin/app/model/tplmanageModel.php#L114)在路径锁内核对基线并推进修订记录。

另外对模板与 CSS 分别执行：读取旧版本 → 删除 → 旧保存为 404 → 用完全相同的字节同名新建 → 旧保存为 409。这验证了保护依赖资源代次，不仅依赖内容不同。重新读取当前版本后，空 CSS 保存正常。

两个 JavaScript 文件语法检查通过，288 组导航回归通过；另以 Node 执行真实设置/模板回调，4 个普通错误与 `responseJSON` 冲突场景均显示消息且不改变编辑页位置。这里不是实际浏览器输入保留验证；本轮未另做 iframe 交互。

## TC04 已解决的部分

[编译写入](../../system/core/template.php#L145)现在检查完整写入、权限及 rename 结果；[控制器渲染](../../system/core/controller.php#L54)持有共享锁并清理失败输出，清理使用同一锁的排他侧。

原确定性故障已通过：保存 B 后将编译目录设为不可写，暖缓存请求返回 **500**，未返回旧 A；移除本轮旧编译文件后，冷缓存同样返回 **500**，不再以 200 表示空白成功。修复目录权限后正常渲染 B。

另以合法测试模板中的短时延迟保持真实执行，确认清理等待约 **0.95 秒（绑定）/ 0.90 秒（原生卷）**，渲染正文完整后才移除缓存。这证明清理与在途执行的锁已经协调，不将剩余问题描述为排他清理锁完全失效。

## TC04 环境限定的剩余并发问题

| 相同交错负载 | 前台结果 | 清理结果 |
| --- | --- | --- |
| 绑定挂载缓存 | 240 次中 238 次完整 200，**2 次受控 500**，0 次空白 200。 | 30 次均为 200。 |
| 容器原生缓存卷 | **240 次全部完整 200**，0 次错误及空白响应。 | 30 次均为 200。 |

绑定失败发生在第 17、21 批（日志下标 16、20）。对应服务日志明确记录编译文件 include 的 `Stale file handle`，随后在[控制器第 61 行](../../system/core/controller.php#L61)抛出“模板编译产物执行失败”，由统一错误处理返回 500。此时目录可写、源码固定，没有继续施加前述权限故障。

**已确认的是响应失败及文件系统差异；底层句柄失效的完整因果链仍待验证。** 源码表明，多个渲染者都持共享锁，并仍可能[重新编译和替换同一产物](../../system/core/template.php#L183)；同名产物的并发发布/打开值得优先检查。这是调查方向，不声称已证明唯一根因。

**修复验收：**保留当前错误传播、缓冲清理及排他清理锁，继续核对同一编译路径的发布与取得过程，确保合法并发读取能获得可执行的完整产物。若对未开始执行时的读取失败设计重新取得/重试，应限定边界，不能对整个模板执行无条件重跑。重放原绑定样本并核验逐响应状态和正文；原生卷的通过不能替代该样本的未通过结果。

若维护者后续明确将编译缓存限定在原生卷或特定可靠文件系统，需另行明确并验收这一部署前提。本轮未替维护者缩小支持范围，因此 TC04 暂保留为 P2；也不将该绑定挂载现象推及所有生产站点或计算为生产故障率。

## TC05 清理范围与幂等性已闭合

[清理实现](../../system/common/template_cache.php#L40)逐个处理前台桌面、前台移动及后台目录，不再要求两侧同时存在。独立 HTTP 重放确认：

1. 两个桌面目录预热后清理，返回实际数量 2。
2. 仅前台重建，再清理返回数量 1，目录确实移除；保留较早时间戳的新源码由旧 A 切换为 B。
3. 空目录状态再次清理返回已空，结果幂等。
4. 实际 iPhone User-Agent 使用移动缓存；三目录清理返回数量 3，移动目录被移除，随后显示保留旧时间戳的新移动源码 B。

两种缓存存储方式均完成这些检查。正式隔离缓存回归另外覆盖各目录单独存在及符号链接拒绝。TC05 可以关闭；清理覆盖面的正确性与 TC04 的剩余并发读取问题分别判定。
