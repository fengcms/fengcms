# 搜索请求与分页契约

搜索页面继续使用原有模板调用 `M("module")->search($_GET, $field, $num)`。此方法是兼容入口：它读取当前请求的分页上下文，再委托给 `moduleModel::searchPage()`。模板文件及调用语法不需要更改。

## 各层职责

- `searchController` 使用 `CmsSearchCriteria::fromInput()` 校验关键词、模型标识和页码；控制器继续检查模型是否启用、关键词是否为空、POST 重定向和搜索频率限制。
- `CmsSearchCriteria` 保存经过语法校验的关键词、模型和页码。它不读取 `$_GET`、`$_POST` 或 `$_SERVER`；直接调用模型时，调用者应自行完成路由权限检查。
- `moduleModel::searchPage($criteria, $pageContext, $field, $num)` 接受显式参数，负责模型选择、绑定搜索词、统计、排序、分页取数，并返回原有的 `list`、`fy`、`total` 结构。
- `CmsPageContext` 保存当前页、分页链接的查询参数、请求路径及脚本路径。`page` 的第四个参数可传入该上下文；原有三参数调用继续从当前请求读取这些值。模板渲染期间的兼容默认值不进入分页链接。

搜索请求只允许第 1 至 100 页。搜索分页器保留真实总数，但最多展示前 100 页的链接；结果超过此范围时，在分页处提示缩小关键词。栏目及后台分页不使用该限制。搜索词包含路径分隔字符或以“下划线加数字”结尾时，`search()` 生成编码的动态查询地址，避免伪静态规则误读关键词。

计数和列表仍使用原有 `UNION` 去重、`time DESC, id DESC, html ASC` 排序、发布状态过滤与字段选择。普通列名搜索复用已审查的只读连接；自定义 SQL 字段表达式仍使用独立连接。

## 验证

- 独立契约测试在全局请求参数故意不同的情况下，确认显式入口仍返回指定的第 2 页；兼容入口得到相同记录及分页链接。
- 现有 HTTP/数据库回归覆盖全站与指定模型、参数拒绝、转义、POST 重定向以及跨页结果。
- 隔离数据副本的 5 组搜索结果与调整前对照：4 组逐字节一致，另 1 组仅有内容页访问造成的动态阅读次数变化。四类搜索的数据库命令数和连接数与调整前保持一致。
