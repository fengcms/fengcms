# 搜索、分页与内容页兼容性审阅报告

日期：2026-10-27。审阅 HEAD：`43ad379`；程序代码基线：`0f1e9da`。本轮只交付审阅文档，没有修改应用、模板、路由或运行配置。

**结论：本轮兼容性验收未完全通过，确认 6 项问题：5 项 P2、1 项 P3。** 普通搜索、跨模型分页和正常内容访问的受控用例通过，但部分系统生成的链接无法被入口正确解析，超过搜索页数上限的链接仍会展示，模型名大小写变体可以触发 500，缺失栏目会产生 PHP Warning。

这些是本轮新增业务范围的发现，不代表都由最近的优化引入。[R1 至 R4 复验报告](PERFORMANCE_R1_R4_RECHECK_2026-10-27.md)中的四项关闭结论保持不变。本报告也不是对历史安全审计的重新验收。

## 审阅范围与方法

沿着“模板辅助函数生成链接 → Nginx 重写 → 请求校验 → 模型查询 → 分页链接及内容渲染”核对调用链，参照[搜索请求契约](SEARCH_REQUEST_CONTRACT.md)和[内容请求收敛记录](CONTENT_REQUEST_HARDENING_2026-10-27.md)。同时检查旧模板入口 `M("module")->search($_GET, $field, $num)` 与显式搜索入口的兼容性。

验证使用本地 Docker 的 PHP 8.4、MySQL 8.4、Nginx。创建数据前核对开发数据库标记；文章、栏目、单页、自定义模型和临时表均使用独立随机标记，最终清理自己创建的数据。HTTP 验证经过实际 Nginx/FPM；辅助函数的两种 `URL_TYPE` 分支在独立 CLI 进程中调用，没有切换站点运行配置。

优先级含义：P2 为需要修复的用户可见功能错误；P3 为异常数据下的健壮性问题。下面的响应码和结果是本地实测，不能直接推定所有客户环境相同。

## SC01：合法下划线名称不能在链接生成和解析间往返

位置：[url()](../../system/common/function.php#L365)、[栏目重写](../../docker/nginx/default.conf#L49)、[栏目创建](../../admin/app/model/classifyModel.php#L170)、[栏目查找](../../app/controller/classifyController.php#L17)。

`url()` 在动态模式下把旧地址按 `_` 全部拆开，再按固定下标读取模型名、栏目名和 ID。模型名和栏目英文名却都允许下划线。后台还会把这些合法值写成 `/<project>_<enname>_<id>.html`，因此生成端与解析端没有一致的分隔契约。

本轮用已注册、已启用且含下划线的临时内容模型验证，也用 `project=article`、`enname=news_local` 的临时栏目验证。下表中的 `<project>`、`<id>` 是实际创建后读取的合法值；随机后缀不构成复现条件。

| 用例 | 实际结果 |
| --- | --- |
| `/?controller=content&project=qa_compat_<随机值>&id=1` | 200，读取正确内容。 |
| `/content_qa_compat_<随机值>_1.html` | 200，内容伪静态规则可正确识别该模型。 |
| 动态模式 `url('/content_qa_compat_<随机值>_1.html')` | 输出 `?controller=content&project=qa&id=compat`，访问为 400。 |
| `/?controller=classify&project=article&classify=news_local&classid=<id>` | 200，读取正确栏目。 |
| 动态模式 `url('/article_news_local_<id>.html')` | 输出 `?controller=classify&project=article&classify=news&classid=local`，访问为 400。 |
| `/article_news_local_<id>.html` | 404；重写把 `article_news` 当作模型、`local` 当作栏目名。 |

**修复要求：**让链接生成和路由解析共同使用能恢复完整字段的契约。栏目地址中的模型、英文名都允许 `_`，仅把一个正则改成非贪婪匹配会把歧义移到另一侧；可以结合末尾数字 ID 查询并核对栏目元数据，或为无法无歧义表示的名称使用兼容的动态链接。保留旧地址和模板调用方式，不应只通过禁止存量合法名称来消除问题。

**验收：**覆盖普通名称、模型含 `_`、栏目名含 `_`、两者均含 `_`，同时验证动态模式、伪静态模式、栏目分页和内容链接。每个生成链接都要经过 HTTP 入口并读取预期记录，而不只断言字符串含有某段文本。

## SC02：部分合法关键词的搜索链接返回 404

位置：[search()](../../system/common/function.php#L405)、[Nginx 搜索规则](../../docker/nginx/default.conf#L47)。

辅助函数对完整关键词执行 `rawurlencode()`，但当前 Nginx 的重写捕获排除了 `/`、`?`、`&`、`=`。以下为同一关键词经动态查询及辅助函数伪静态链接访问的对照：

| 关键词 | 动态查询 | 辅助函数生成的路径 | 路径实际结果 |
| --- | --- | --- | --- |
| 普通中文 | 200，词值一致 | `/tags/%E6%99%AE%E9%80%9A%E4%B8%AD%E6%96%87.html` | 200，词值一致。 |
| `C++` | 200，词值一致 | `/tags/C%2B%2B.html` | 200，词值一致。 |
| `A&B` | 200，词值一致 | `/tags/A%26B.html` | 404。 |
| `a/b` | 200，词值一致 | `/tags/a%2Fb.html` | 404。 |
| `x=1` | 200，词值一致 | `/tags/x%3D1.html` | 404。 |
| `what?` | 200，词值一致 | `/tags/what%3F.html` | 404。 |
| 字面值 `literal%2F` | 200，词值一致 | `/tags/literal%252F.html` | 200，词值一致。 |

这会影响搜索标签等使用 `search()` 生成的链接。本轮没有观察到 `C++` 或字面百分号字符串被错误解码，不能把问题泛化为所有特殊字符都损坏。

**修复要求：**为不能安全往返于当前路径语法的关键词返回 RFC 3986 编码的动态查询链接，或实现生成端、Web 服务器和请求解析共同支持的编码协议。当前路由限制还承担阻止路径内容注入查询参数的职责，不能直接移除捕获限制或恢复任意查询串拼接。

**验收：**用上表逐一核对最终关键词、状态码和分页后的关键词；额外保留伪静态路径不能覆盖 `controller`、`project` 等路由参数的安全回归。Apache 必须独立实测后再宣称兼容。

## SC03：以“下划线加数字”结尾的关键词被当作分页

位置：[search()](../../system/common/function.php#L408)、[优先匹配的分页规则](../../docker/nginx/default.conf#L47)、[页码校验](../../app/searchCriteria.php#L22)。

`rawurlencode()` 保留下划线，而 `/tags/<关键词>_<页码>.html` 的分页规则先于普通搜索规则执行。

| 输入 | 动态查询结果 | 辅助函数链接结果 |
| --- | --- | --- |
| `part_2` | 200，关键词 `part_2`。 | `/tags/part_2.html` 返回 200，实际关键词变成 `part`。 |
| `part_2026` | 200，关键词 `part_2026`。 | `/tags/part_2026.html` 返回 400，`2026` 被作为页码拒绝。 |

前一项可能悄悄返回另一组结果，比单纯 404 更难发现。[Apache 规则](../../.htaccess#L23)也存在先匹配分页的语法，本轮只作静态核对，不把它记作 Apache 实测。

**修复要求：**对有分页歧义的关键词使用动态链接，或设计无歧义且兼容旧分页地址的表达方式。仅手工把 `_` 替换成百分号编码不能代替完整的 Web 服务器往返验证。

**验收：**覆盖 `part_2`、`part_2026`、`part_0`、多重下划线和普通关键词的第一页、下一页、末页。检查关键词及结果集合，不以 HTTP 200 单独判定成功。

## SC04：分页器生成搜索入口拒绝的页码

位置：[搜索页码上限](../../app/searchCriteria.php#L22)、[总页数计算](../../system/core/page.php#L78)、[末页链接](../../system/core/page.php#L266)、[搜索分页调用](../../app/model/moduleModel.php#L258)。

搜索请求仅允许 `page=1..100`，但分页器直接按总数计算全部页数，没有搜索范围的上限。指定模型搜索模板每页 10 条。

本轮创建 1001 条匹配独立关键词的已发布文章，结果如下：

| 请求 | 实际结果 |
| --- | --- |
| 指定模型第 1、2、100 页 | 均为 200，每页 10 条匹配记录；页面均包含指向第 101 页的链接。 |
| 点击第 101 页链接 | 400。 |
| `page=0` 对照 | 400，边界拒绝仍生效。 |

因此总数显示包含第 1001 条记录，但系统提供的搜索链接无法取回它。全站搜索默认每页 100 条，按同一实现推导，超过 10000 条结果时也存在此矛盾；本轮没有构造 10001 条数据实测该阈值。

**修复要求：**统一搜索入口与分页展示的资源上限。若保留最多 100 页，应限制搜索上下文中的可访问页数并清楚表达真实总数与可浏览范围；不得继续展示不可用链接。若调整上限，需要同步评估数据库成本。不要在通用分页器中无条件限制所有栏目和后台列表，也不要仅删除请求上限。

**验收：**覆盖 0、1、刚好 100 页和超过 100 页的结果，检查首页、下一页、末页及手工请求。保留越界参数校验，并确保页面宣称可访问的每个页码都能成功打开。

## SC05：内容模型名大小写变体触发 500

位置：[内容参数校验](../../app/contentRequest.php#L13)、[模型授权及调用](../../app/controller/contentController.php#L24)、[内容表查询](../../app/model/moduleModel.php#L280)。

请求校验允许大小写字母。模型元数据查找在当前数据库排序规则下大小写不敏感，但控制器没有采用查询返回的规范模型名，而是把原始请求值继续作为实际表名。当前数据库 `lower_case_table_names=0`，表名区分大小写。

使用同一条已发布、有效的临时文章：

| `project` 参数 | 实际结果 |
| --- | --- |
| `article` | 200。 |
| `ARTICLE` | 500。 |
| `Article` | 500。 |

这不是要求大小写变体一定返回 200；问题在于授权检查与查询目标不一致，格式通过后走到不存在的表并产生服务端错误。表名不区分大小写的环境可能掩盖此问题。

**修复要求：**明确大小写契约：要么严格核对与已注册名称完全一致，不一致则返回 400/404；要么用元数据返回的规范名称继续查询。不要一律把字符串转成小写，因为历史注册模型可能本身包含大写。内置 `single` 的行为也应明确。

**验收：**在表名区分大小写的数据库上覆盖规范名称、全大写、混合大小写、真实注册的混合大小写模型、停用模型及不存在模型。禁止出现 500；被拒绝的请求不得更新阅读次数。

## SC06：内容栏目不存在时出现 PHP Warning

位置：[内容补全栏目名](../../app/model/moduleModel.php#L292)、[classname()](../../app/model/classifyModel.php#L34)。

`classname()` 查询不到栏目时，直接读取空结果的 `name`。本轮最初的已发布内容夹具使用 `classid=0`；内容请求返回 200，但 PHP-FPM 日志出现 3 条指向 `app/model/classifyModel.php:36` 的 Warning。随后使用有效栏目的对照用例可以正常读取栏目名。

因此即使仅检查 HTTP 200 也会漏掉此问题。它依赖无所属栏目或栏目已不存在的数据，未在所有正常文章上出现；本轮直接实测的是 `classid=0`，非零孤儿栏目属于相同空结果分支的源码判断。

**修复要求：**对未查到栏目作显式处理，并按业务约定返回空栏目名、替代面包屑或明确 404。不能用 `@` 抑制错误，也不要在没有约定时把全部历史无栏目内容直接下线。

**验收：**覆盖 `classid=0`、不存在的非零栏目及有效栏目，检查正文、栏目显示、阅读次数与实际 PHP 日志。即使决定返回 404，也应在更新阅读次数前完成相关有效性判断。
