## 流程与边界

`editor.js` 在创建 wangEditor 之前为每个字段捕获独立原文字符串。`legacy-richtext.js` 提供查看原文、确认、预览、应用和一次撤销。原文不会被 `sync()` 或当前编辑结果覆盖。清洗接口 `/admin/api/richtext.php` 只接受已登录后台账号的 POST/CSRF 请求，正文限制 2MB，使用既有 HTML Purifier 策略；不接收模型、字段、记录 ID，不查询或写入文章。超级管理员、编辑均可使用。Apache、Nginx、IIS 的 PHP 入口白名单已同步新增此接口。

确认后先检查不支持的结构，再请求服务端清洗原文，在浏览器执行 Turndown + GFM → markdown-it（html:false），随后再次服务端清洗。文字去除空白后的内容及图片、链接地址顺序必须一致，否则停止。复杂表格（含跨度属性、嵌套或无表头）、iframe、音视频、对象与 SVG 拦截并提示人工处理。Markdown 不能无损保留历史样式，普通字体、尺寸、颜色、浮动等信息可能丢失。

预览使用无权限 sandbox iframe 与限制资源的 CSP，允许图片显示，禁止脚本、表单和父页面访问。应用时再交给当前 wangEditor 解析，检查文字及资源完整性；失败则恢复优化前编辑区。普通保存流程继续执行服务端清洗。空原文禁用按钮，上传未完成时阻止优化，异步预览后若编辑区已变化则阻止应用。撤销覆盖后续修改时另行确认。页面不自动保存文章，也不提供跨刷新恢复；操作前仍需站点备份。

正文替换前取消选区、失焦，避免 setHtml 恢复失效选区。多个字段初始化不自动聚焦，避免编辑器之间抢占选区。各字段快照独立。

## 依赖与构建

实际发行包版本及传递依赖见 `admin/public/legacy-richtext/PROVENANCE.json`：Turndown 7.2.4、turndown-plugin-gfm 1.0.2、markdown-it 15.0.3。部署只使用本地 JS，不需要 Node 或外网 CDN。主库为 MIT，entities 为 BSD-2-Clause，各组件许可证随目录保存。构建工具和仅构建时依赖按锁文件安装，含不进入浏览器包的依赖，不应笼统将所有构建依赖声明为 MIT。

构建：`npm ci --prefix tools/vendor && node tools/vendor/build-legacy-richtext.cjs`。构建脚本根据 esbuild 实际输入记录依赖版本、许可证并计算包摘要；提交生成文件。运行 `python3 tools/verify-dependencies.py` 校验摘要。第三方包安全更新需重新核验实际转换结果；不能直接修改压缩包。

## 初始化失败与图片链接往返补充

2026-10-29。实际历史正文中发现：以段落外图片开头并混合长段落、图片链接时，直接把整篇 HTML 传给 `createEditor` 会触发 Slate 节点路径异常，导致初始化中断。改用空正文创建编辑器，再用 `setHtml` 回填；不恢复 span 自动拆分或默认 Markdown 重排。

若回填仍抛出异常，保留原文、只读原始文本框与优化入口，隐藏不可用编辑区并阻止保存。此字段不参与空编辑器同步，其他字段仍可正常初始化。优化成功后解除保护；撤销恢复到失败前状态时，原文和保存保护也恢复。Node 回归模拟解析异常，覆盖同步、保存阻止和解除及撤销。

转换策略补充：相邻中文加粗/斜体片段在 Markdown 标记外明确加入空白边界，避免中文标点导致标记被当成正文；去除空白后的文字仍必须完全一致。图片超链接在标准 HTML 中使用 `a > img`，而 wangEditor 使用 `img[data-href]` 并在解析时执行 URI 解码。适配层在交给编辑器时进行编码及结构映射，同步表单时重新生成标准图片链接，避免中文编码参数变化或服务端清洗丢失图片链接。此映射只用于编辑器与标准 HTML 之间的表示交接，不批量改写历史正文，也不拆分 span。空的无文字、无图片锚点不作为可见链接资源参与完整性检查。

脱敏浏览器样本覆盖段落外图片、连续中文强调、20 个链接图片段落及编码查询参数；验证 HTML → Markdown → HTML → 编辑器 → 标准 HTML → 服务端清洗 → 再次编辑的文字、图片与可见链接均保持完整，最终浏览器控制台无错误。真实历史数据副本的相关正文已验证编辑器正常初始化，主动优化后保留 22 个图片引用与 11 个有效图片链接。未保存该历史文章，数据库原文未改动；记录中不保留客户标识或正文。
