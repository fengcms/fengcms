## CM03 原失败请求与结果明细

[批量执行](../../admin/app/model/contentWrite.php#L155)设置约 12 秒的循环预算，[命名锁等待](../../admin/app/model/contentWrite.php#L35)取单次 5 秒与剩余预算中的较小值。预算到期后，尚未开始处理的 ID 返回 `unprocessed`，不再持续为后续每项等待完整的 5 秒。

本轮使用带 `f_dev_meta` 标记的开发数据库和独立临时模型，创建 14 条状态为 1 的记录。第一条允许执行，独立连接持有另外 13 条的记录命名锁，经真实 Nginx/PHP-FPM 发送批量回收请求；没有改变服务器超时配置。

| 观察项 | 上次失败结果 | 本轮结果 |
| --- | --- | --- |
| HTTP 及耗时 | 约 60.02 秒，504。 | 约 12.019 秒，200。 |
| 响应结构 | 网关错误页，没有逐条 JSON。 | `status=p`，五组 ID 明细齐全。 |
| `changed` | 无法从响应得知。 | 第 1 条，共 1 条。 |
| `failed` | 无法从响应得知。 | 第 2 至 4 条，共 3 条。 |
| `unprocessed` | 无法从响应得知。 | 第 5 至 14 条，共 10 条。 |
| `already`、`missing` | 无明细。 | 均为空数组。 |
| 数据库状态 | 第一条已回收，其余未变。 | 第一条为 -1，其余 13 条为 1，与明细相符。 |

独立断言核对了五组数组的并集等于全部输入 ID，组间无重复，没有漏报或把未执行项标成完成。上表是同一失败请求在本地环境的对照，不作为一般性能提速比例。

释放 13 条记录锁后，用原 14 条选择集重试：第一条进入 `already`，其余 13 条进入 `changed`，最终全部为 -1，`unprocessed` 为空。再重试一次，14 条全部为 `already`，没有再次改变数据。

最新正式 HTTP 回归还覆盖 500 个 ID 的预算耗尽请求，确认响应在等待时限前返回，并验证剩余分组及后续重试。本轮未把该正式用例的结果替代上面的独立 14 条原场景重放。

[结果摘要函数](../../admin/js/navigation.js#L19)已包含“尚未处理，请重试”。本轮另用 Node 支架执行内容列表及回收站的实际回调，确认摘要包含未处理 ID 和数量，并触发一次刷新。模板中的模型值使用固定合法占位值替换；该检查不等于真实浏览器整页验收。

## CM07 原 SQL 行锁时序与两种交错顺序

[关系锁作用域](../../admin/app/model/contentWrite.php#L35)统一为跨模型的 `all-categories`。内容保存、栏目单条/批量删除、清空及栏目创建使用同一关系锁；[递归处理](../../admin/app/controller/classifyController.php#L238)按每个节点的实际 `project` 处理内容，不再把根模型用于整个子树。栏目新增和批量新增也在[关系锁内](../../admin/app/controller/classifyController.php#L256)执行，减少子树检查与变更间的窗口。

本轮独立创建两个临时内容模型 A、B，通过真实后台接口建立三级结构：A 父栏目 → B 子栏目 → A 孙栏目，并增加一个外链子栏目。没有用 SQL 强插不被后台接受的层级。各内容模型均有独立测试内容。

对父栏目单条删除、批量删除、清空分别执行上次的失败时序：

1. B 模型内容起初未分类，获取真实编辑签名。
2. 独立连接锁住该 InnoDB 内容行，提交将内容归入 B 子栏目的正常编辑请求。
3. 在数据库进程列表中确认实际 UPDATE 已等待 SQL 行锁，并确认保存请求持有跨模型关系锁。
4. 另一编辑通过真实后台接口处理 A 父栏目。
5. 处理请求返回后释放 SQL 行锁，检查原保存结果，再重试父栏目操作。

| 父栏目操作 | 保存等待期间 | 释放 SQL 行锁后的保存 | 再次执行父栏目操作 |
| --- | --- | --- | --- |
| 单条删除 | 409；四个栏目及原有内容均保留。 | 200，引用仍存在的 B 子栏目。 | 删除成功，各模型内容及全部栏目删除。 |
| 批量删除 | 409；没有部分删除。 | 200，栏目关联有效。 | `status=y`，按各节点实际模型删除内容及全部栏目。 |
| 清空 | 409；没有部分清空。 | 200，栏目关联有效。 | 内容清空，四个栏目保留，外链栏目及其 URL 不变。 |

因此上次“父栏目删除成功、子栏目已不存在、原保存仍成功引用其 ID”的结果未再出现。删除被阻止时，没有先删除根内容或其他模型的内容。

另验证删除先完成的顺序：让 B 内容编辑请求在记录命名锁上等待，在此期间由另一会话删除 A 父栏目及 B 子栏目，再释放记录锁。删除返回 200，旧编辑保存返回 400，内容仍为未分类，没有写入失效栏目 ID。两种交错顺序均得到明确且一致的结果。
