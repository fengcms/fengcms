# TC06 模板保存后的内容刷新修复

依据[TC04 关闭复审](TEMPLATE_CACHE_TC04_CLOSURE_2026-10-28.md)处理 TC06。复审观察到：模板源码位于绑定挂载、编译缓存位于原生卷时，后台保存后的源码时间戳可能比编译文件早 1 秒；旧的过期判断会一直复用旧正文。

## 修改

- 渲染每次读取模板源码并计算 SHA-256，与编译文件头部的源码摘要比较。只要内容变化就重新编译，源码时间戳早于、等于或晚于缓存时间都不会导致旧内容持续显示。读取到的同一份源码字节也直接交给编译器，避免哈希与编译内容来自两次不同的文件读取。
- 编译器自身更新仍通过其时间戳触发重新编译；原有逐模板读写锁、渲染与清缓存锁、编译写入失败处理均保留。模板文件及 `{include ...}` 等语法未修改。
- 该方式在每次模板读取时增加一次完整源码读取和哈希计算，换取跨文件系统时间戳不可靠时的准确刷新。请求内重复引用同一子模板仍复用已持有的编译文件与锁。

## 验证

- 缓存专项分别在容器原生临时目录和本机绑定挂载临时目录通过，覆盖源码时间戳落后、相等时源码不变、子模板刷新，以及正在执行旧版本时新版本等待发布。
- 主 HTTP 回归增加真实后台保存后的前台读取，并人为把保存后的源码时间戳调早，验证后续请求显示新版。设置时间戳只用于确定性制造复审中的时间顺序。主回归 **617 项通过**，其中新增用例明确通过。
- `./bin/dev check`：PHP 8.4.27，353 个文件，0 个语法错误。`./bin/dev test` 的原有全套专项通过；新增 HTTP 用例后再单独重跑了主回归。生产 PHP-FPM、OPcache、网络文件系统及多节点环境仍需按实际部署验证。
