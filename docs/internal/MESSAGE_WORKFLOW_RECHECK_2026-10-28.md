## 原失败场景重放

### LM01：待审核留言泄露到公开列表

使用隔离数据库创建待审核留言后，以匿名 HTTP GET 请求实际前台留言列表，响应正文不含该留言标题。将该记录发布后再次请求，正文包含该标题。该结果覆盖公开列表调用链，而非仅检查模型的备用分页方法。

### LM02：旧表单覆盖与删除竞态

从同一留言读取编辑基线，先提交回复 A，再用旧基线提交回复 B。A 返回成功，B 返回 HTTP 409，数据库仍保存 A。重新读取并原样保存同值数据，操作成功。

并发删除场景中，测试连接先持有记录行锁，再提交真实后台回复 HTTP 请求；确认其 UPDATE 已排队后删除记录并提交。回复请求返回 HTTP 404，记录保持不存在，没有误报成功或重新创建。

### LM03：批量部分完成后使用原请求重试

将第二项的 BEFORE DELETE 触发器设为故障点。第一次批量请求返回部分完成状态；移除故障后，对同一组 ID 发起重试，返回成功且这组三条记录均不存在。该场景分别在 InnoDB、MyISAM 留言表重放通过。

### LM04：空字段与普通文本遭旧过滤破坏

通过后台真实 HTTP 回复保存入口提交空昵称、电话、邮箱，QQ 值 `0`，以及包含 `https://example.test/a/b`、标记文本、实体文本、中文和换行的回复。请求成功，数据库字段与提交字符串逐字一致。

### LM05：请求结果不确定及插入失败后重试

以相同表单提交标识和内容连续调用保存逻辑，第二次返回恢复结果，ID 与首次插入相同。另在 INSERT 前注入 SQL 故障：首次调用失败时验证码仍在会话中；移除故障后用相同提交标识和验证码重试，成功创建一条记录。

同提交标识恢复是在模型保存路径上直接重放；本轮没有在网络层主动丢弃一个已完成 HTTP 请求的响应。接口的重试行为及数据库唯一约束已由上述模型级场景验证，传输层断连本身未独立注入。

### LM06：确认框在请求之后才出现

运行 `node tests/message-form-regression.js`。取消确认时请求计数为 0；确认后请求计数为 1，成功与验证码错误回调表现符合预期。
