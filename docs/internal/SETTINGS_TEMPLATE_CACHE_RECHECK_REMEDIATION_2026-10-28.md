# 模板缓存并发复查补修

依据[复查报告](SETTINGS_TEMPLATE_CACHE_RECHECK_2026-10-28.md)处理 TC04 的绑定挂载并发遗留。报告确认原生卷 240 次请求全部成功，绑定挂载 240 次中有 2 次在执行编译文件时遇到 `Stale file handle`。这是已测文件系统组合的结果，不代表生产故障率。

## 实现

- 每个模板源路径对应一把私有运行目录中的文件锁。缓存命中时持共享锁读取编译文件；需要编译时升级为排他锁，再核对一次状态并发布，随后降为共享锁。这样同一路径的发布不会与正在执行的编译文件交错，且普通并发读取仍可共用锁。
- 顶层和 `{include ...}` 片段执行期间保留各自的共享锁，在渲染结束时释放。编译结果仍在原来的 PHP 变量作用域中 `include`，没有改动模板文件及其调用语法。
- 源文件与编译文件时间戳相等时，核对编译文件中的源码 SHA-256 标记。内容未变时不再重复替换同名产物；同秒更新可触发重新编译。仍保留早于编译产物的旧时间戳源码需要手动清缓存的既有规则。
- 原有全局渲染/清理锁、写入失败报错和输出缓冲清理保持生效。

## 验证

- `./bin/dev check`：PHP 8.4.27，353 个 PHP 文件，0 个语法错误。
- `./bin/dev test`：完整回归通过，包括主 HTTP/数据库、模板编译、隔离导入、备份及结构一致性专项。
- `sh tests/template-cache-regression.sh`：分别在容器原生目录和本机绑定挂载目录通过。新增确定性交错：一个进程正在执行编译产物时，另一进程更新同一模板，确认更新等待原执行完成，原输出完整，新产物随后可读；相等时间戳且源码未变时不会更换编译文件 inode。原有暖/冷失败及清理锁测试也通过。

此次绑定挂载验证是隔离 PHP 进程的确定性并发测试；未重放复查报告中 240 次 HTTP 请求和 30 次清理的完整负载，也未验证生产网络文件系统、跨主机锁或 OPcache 配置。部署到具体站点前仍应在其缓存文件系统上做并发复测。
