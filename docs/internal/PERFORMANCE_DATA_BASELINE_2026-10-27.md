# 隔离数据副本的性能基线与首轮优化

日期：2026-10-27。依据[性能优化复审闭环与下一步计划](PERFORMANCE_OPTIMIZATION_FOLLOWUP_2026-10-27.md)，本轮使用维护者控制的隔离数据库副本测量查询行为。本文不包含站点标识、业务内容、搜索词或数据库凭据；原始请求与执行计划保存在 Git 忽略的私有台账中。

## 方法与数据边界

- 本地运行环境：PHP 8.4.27、MySQL 8.4、Nginx，单并发。测试站点使用独立数据库账号、独立缓存卷和仅监听本机的端口，原开发库未切换。
- 副本约有 7 千条文章，其中公开状态约百条；另有 4 个启用搜索的内容模型。导入数据原为 MyISAM。一个无权读取的存储过程未包含在副本中，旧正则语法的一个视图仅在本地做了兼容调整。
- 覆盖首页、浅层/深层栏目、较长内容、站点地图、标签、全站及文章搜索的高命中与空结果，共 10 类请求。每类清理前台文件缓存后测 1 次冷请求，再预热 3 次、串行测 20 次热请求。数据库缓冲池和 PHP OPcache 没有随单项清空。
- 时间取本机 HTTP 完整响应，中位数及最近秩 P95 单位为毫秒。`Questions` 是 MySQL 按测试账号统计的客户端命令数，含协议命令；连接数取同账号累计连接差值。内存取 PHP 请求峰值。它们不等同于线上吞吐量或纯 SQL 语句数。

## 三阶段结果

B1 为原代码、无新增索引；B2 仅让已审查的搜索 `SELECT` 复用普通连接；B3 再在隔离副本文章表增加 `(status, id)` 索引。每格为热请求“中位数 / P95”。

## 执行计划与改动判断

1. 搜索涉及 5 个模型。由于条件为 `LIKE '%词%'`，B2 的高命中和空结果执行计划均扫描各模型的候选行，普通 B-tree 索引不能直接完成该匹配。当前 `UNION` 承担跨模型去重，指定模型的字段选择也供旧模板使用。本轮保留去重、字段、排序、分页和模板调用语法；没有引入全文索引或改写搜索结果身份。
2. 文章表大部分记录不处于发布状态。B2 的首页文章相关语句每请求累计检查约 5.5 万行；B3 使用 `idx_status_id` 后约为 900 行，相应数据库等待时间约从 108 ms 降至 5 ms。站点地图和标签页未依赖文章表扫描，耗时基本不变。这组变化支持新增索引，且解释了页面时间下降的主要来源。
3. 对索引有无做了本地 A/B 结果对照：10 类页面的搜索结果区域或内容链接序列一致，动态点击数已排除。搜索连接改动前后另对照 5 组搜索结果（含第 2 页），结果区域逐字节一致。

搜索连接改动见提交 `87ed0d0`。新安装的文章表索引和现有站点手工迁移说明见提交 `b37e3df` 与[文章发布状态索引迁移](PERFORMANCE_INDEX_MIGRATION.md)。本轮只在隔离副本执行索引 DDL；现有站点需分别检查索引、备份与维护窗口。

## 验证与后续

- `./bin/dev check`：335 个 PHP 文件，0 个语法错误。
- `./bin/dev test`：478 项 HTTP/数据库回归与隔离导入演练通过。
- 新安装 SQL 在随机命名的空数据库中实际导入，确认索引列顺序为 `(status, id)`，随后删除该临时数据库。
- 隔离站点 10 类路由均返回 HTTP 200；索引试验后两处视图仍可查询。原开发站点仍使用原数据库。

下一步应在其他具有不同发布比例和表引擎的副本上复测索引收益，并测并发场景。自定义模型索引逐表决定。若继续优化搜索，可先测字段能力批量读取与查询构造开销；改变 `UNION` 或字段集之前，须准备跨模型重复数据和自定义模板的结果一致性用例。

本次数据来自单一隔离副本，MySQL 8.4 的执行计划也不能直接代表旧版 MariaDB 或共享主机。MyISAM 无锁导出不是事务级快照；这些数字不能外推为生产提速比例。
