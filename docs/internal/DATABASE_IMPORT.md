# 后台数据库导入

后台「数据库管理 → 导入备份」适合同版本、同模型结构、数据量较小的网站。可以在「备份列表」点「导入」，也可以上传由本系统生成的 `.sql` 备份文件。上传上限为 8 MB、10,000 条记录；大数据量建议使用虚拟主机面板或数据库客户端。

导入分为**预览**和**确认**两步。预览核对表、视图、列类型、记录数与文件哈希。确认时程序先阻止新的 CMS 写入并等待正在进行的写入完成，再自动创建一份当前数据库备份；备份失败则不会改动数据库。随后用参数化语句把备份记录写入临时表，核对记录数后整体交换同名表；上传的 SQL 文本不会作为 SQL 命令执行。完成后可在备份列表下载导入前的备份。独立插件、外部脚本或数据库客户端的写入不受 CMS 停写屏障约束，恢复前必须另行暂停。

连接意外中断时，后台会保留本次导入的精确表映射，暂停新的内容、结构与附件写入，也暂停新的备份和导入预览。登录、只读页面和受保护的恢复入口仍可使用。「导入备份」页面出现「核对并恢复中断导入」按钮；核对和清理成功后，重新预览原备份再确认。

交换前，系统记录暂存表的列与行指纹。若连接在交换后中断，恢复前会核对当前正式表；只要发现数据已变化或缺少核对记录，就拒绝自动回退并保留正式表、旧表和恢复记录。此时先在独立副本保全并比较两套数据，由管理员人工决定如何合并或恢复，不能删除恢复记录后直接继续写入。表状态不完整也会拒绝自动清理。自定义代码或外部 SQL 未加入 CMS 写入协议，恢复期间仍须单独停写。

此功能恢复的是**数据记录**，当前站点的表结构、索引和视图定义保持现状。因此，目标站必须先具有完全相同的表名、列名与列类型，以及相同的视图名称；新增或删减模型、升级后表结构变化、外键和触发器都可能使预检拒绝导入。后台导入还依赖数据库账号具备建表、重命名表、删除表及一致性备份所需权限；[MySQL RENAME TABLE 文档](https://dev.mysql.com/doc/refman/8.4/en/rename-table.html)列出了交换表所需权限。发生预检或写入错误时，现有表不会被部分记录覆盖；交换后如需回退，使用自动生成的导入前备份。

数据库备份不包含上传文件、网站源码和私有配置。跨服务器迁移时，这些文件应单独复制，并先在独立站点副本演练。若站点数据或文件超过后台限制、表结构不同，使用主机数据库工具在隔离副本恢复完整 SQL，再核对业务页面。不要将未知来源的 SQL 文件交给主机面板直接执行。

本地 `./bin/dev test` 包含隔离数据库导入回归，覆盖 MyISAM/InnoDB 混用、视图、NULL、二进制、中文、补充平面字符、冲突失败与额外 SQL 拒绝。另在 MariaDB 10.11 的独立容器运行了同一演练。线上虚拟主机的权限、请求时限和定制结构仍需逐站检查。
