## 行为与验收

2026-10-27 复查补充：针对[复查报告](CONTENT_WRITE_CONSISTENCY_RECHECK_2026-10-27.md)中的 CM03、CM07 剩余竞态，批量单项锁超时现在进入 `failed` 明细，后续 ID 继续处理；单条锁超时仍返回 HTTP 409。新增、编辑、栏目转移和后台栏目删除共用按模型划分的关系锁，写入前在锁内核对目标栏目。栏目删除先取得关系锁，再修改栏目及其内容；内容写入先取得记录或创建请求锁，再取得关系锁，避免相反的加锁顺序。栏目被另一请求先删除时，本次写入拒绝且不留下创建记录或计数。

## 旧站升级

升级旧站必须先完整备份数据库、代码、上传文件与私有配置，在副本演练，然后安排停写窗口。先使用正确的 `DB_*` 与 `DB_PREFIX` 配置执行 `php tools/migrate.php`，再部署本次代码。迁移只新增 `content_recycle_state` 与 `content_create_request` 两张 InnoDB 表，可重复执行；缺表时新写入会失败，不能把失败当作成功。新的安装 SQL 已包含这两张表。`./bin/dev up` 会对带开发标记的本地数据库执行同一迁移。

旧 MyISAM 业务表未自动转换；可参照 [数据库迁移说明](SCHEMA_MIGRATION.md) 在副本逐表核对后规划 InnoDB 转换。不得直接以安装程序覆盖旧站数据库。回退旧代码前应恢复同一时间点的代码与数据库备份，避免旧代码绕过请求键与状态记录。

## 异常恢复边界

MyISAM 无事务。已捕获的 SQL 异常由创建流程补偿；进程、主机或数据库在两条 SQL 之间突然退出时，不能声称多表原子提交。创建请求表会保留 `processing` 状态，此键的再次提交会返回 409，阻止自动重复创建。管理员应在数据库副本上查看 `content_create_request` 的 `processing` 行、`record_id` 及对应模型表，核对生成链接和热度，再决定修复记录或将请求改为 `failed` 后重试。`record_id` 为空时也不能直接认定没有遗留记录：进程可能在 INSERT 之后、记录 ID 写入请求表之前退出。不要仅凭错误页面再次使用新请求键。

InnoDB 的事务提交若因连接中断而结果未知，服务端也不会把请求标记为可直接重试；应先核对请求表与内容表。

回收状态先写入辅助表，再更新旧 MyISAM 内容表。若中途退出而内容仍为原状态，下次回收会刷新同一条状态记录；若还原后辅助表尚未清除，下次回收也会覆盖旧状态。历史缺少辅助记录的回收内容一律先恢复为草稿，避免误发布。定期在副本上核对辅助表与内容表中实际行、状态的对应关系。

签名和数据库互斥锁协调本系统后台写入；绕开后台直接改数据库的旧脚本不受该互斥锁约束，应停用或单独迁移。数据库字段校验覆盖当前模型元数据与物理列；新增自定义字段后，应按字段类型验收其服务端规则。
