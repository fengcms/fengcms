# 搜索与内容页兼容性修复结果

日期：2026-10-27。对应[兼容性审阅报告](SEARCH_CONTENT_COMPATIBILITY_REVIEW_2026-10-27.md)。代码提交：`850fc03`、`dcdfc3a`。保持原模板文件及 `{$变量}`、`{loop ...}`、`url(...)`、`search(...)` 的使用方式。

| 问题 | 处理结果 |
| --- | --- |
| SC01 | 栏目伪静态地址把完整标识传给控制器，由尾部 ID 查询栏目并核对模型名及英文名；动态模式的 `url()` 不再按下划线固定拆分，生成根路径查询链接，避免在伪静态页面相对解析。含下划线的栏目翻页生成明确的动态页码链接。原有显式查询地址继续可用。 |
| SC02 | 对含 `/`、`&`、`=`、`?` 的关键词生成 RFC 3986 编码的动态地址。普通关键词仍可用伪静态地址。Apache 重写使用 `B` 标志保护 `+` 等字符，并限制捕获内容。 |
| SC03 | 对以 `_数字` 结尾的关键词生成动态地址，避免与旧分页路径冲突。旧的有歧义伪静态路径仍按原分页含义解析；新生成的链接不再使用它。 |
| SC04 | 搜索请求和搜索分页器统一为最多 100 页，真实命中总数保持不变；超出可浏览范围时给出提示。栏目及后台列表分页不受此上限影响。 |
| SC05 | 内容模型的请求名称必须与注册名称逐字一致；实际注册的混合大小写模型可以正常访问，大小写变体、停用或不存在的模型返回 404，不会触发错误表查询或增加文章阅读次数。 |
| SC06 | `classid=0` 或栏目已删除时返回空栏目名；内容仍按发布状态正常展示，阅读次数仍只增加一次。 |

修复中另发现模板渲染临时补齐的空查询参数会进入分页链接，使“下一页”返回 400。分页上下文现只使用进入模板前的请求参数，并在渲染结束后恢复原上下文。

## 验证范围

- `./bin/dev check`：342 个 PHP 文件无语法错误。
- `./bin/dev test`：488 项原有 HTTP/数据库回归，以及新增的链接辅助函数、搜索契约和 73 项兼容性 HTTP 检查通过；隔离数据库导入演练通过。测试输出无 PHP 诊断。
- 新增兼容性 HTTP 检查分别经本地 Nginx 和临时 Apache 2.4 容器运行，各 73 项通过，包含链接实际访问、搜索词翻页、1001 条结果的首页与末页、栏目分页、拒绝路径参数覆盖、大小写和缺失栏目。临时 Apache 容器已移除。
- 本地隔离数据副本的首页、两种栏目页、长内容页和高命中搜索页均返回 200；没有修改生产站点。该副本的旧模板子导航仍存在独立的 `type` 字段读取 Warning：查询只选了 `id,html,name,url_type`，模板却读取了 `type`。这不属于审阅报告的 SC06，且本轮保持模板文件不变；因此不把隔离副本日志描述为零诊断。

本轮未发布或推送代码。维护者未跟踪的 `template/goods_search.html` 未纳入提交。伪静态路径本身无法同时表达“栏目英文名末尾数字”和“该栏目的页码”两种完全相同的字符串；控制器优先匹配完整栏目地址，新生成的栏目分页链接使用动态页码消除冲突。
